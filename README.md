
# Campfire — «Костёр»

Campfire — собственный движок и работающий на нём клиент симуляционной RTS
об автономной общине бронзового века. Источник истины по
дизайну — `doc/ancient_settlement_rts_gdd_v0.1.md`. Решения, которыми закрыты
открытые вопросы GDD, и список известных пробелов — `doc/DECISIONS.md`.

**Продолжаете работу с нуля?** Начните с `doc/HANDOVER.md`: там состояние проекта,
твёрдые правила, объяснение модели спроса, слабые места и список ловушек, на
которые уже наступали.

Текущее состояние: первый вертикальный срез (§14 GDD) на гексовой сетке. Базовая
культура — месопотамская: община из 8–12 человек приходит в речную пойму обученной
(пашет, пасёт, ткёт, печёт, лепит горшки, формует сырцовый кирпич) и приводит с
собой стадо овец. Без единого приказа игрока она сама размечает себе угодья, ставит
очаг и амбар, строит сначала тростниковые шалаши, потом дома из сырцового кирпича,
распахивает пойму, сеет и жнёт полбу, стрижёт и доит скот, шьёт и **надевает**
одежду, посылает двоих разведчиков расширять известную землю и переживает зимы.
На всех проверенных seed'ах доживает до десятого года.

## Сборка

```bash
nice cmake -S . -B cmake-build-relwithdebinfo -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
nice cmake --build cmake-build-relwithdebinfo -j 2
```

Клиент тянет SDL3 и SDL_image через `FetchContent` (первая конфигурация — несколько минут).
Без него:

```bash
cmake -S . -B cmake-build-relwithdebinfo -G Ninja -DASR_BUILD_CLIENT=OFF
```

## Запуск

В CLion готовы конфигурации (`.idea/runConfigurations`): **Game**, **Game (new
world)**, **Headless (1 year)**, **Headless (10 years)**, **Explain decisions**,
**Content validator**, **Tests**. Основные прогоны собираются профилем
`RelWithDebInfo`; Debug-сборка симуляции примерно на порядок медленнее.

Из терминала то же самое даёт `run.sh` (сам сконфигурирует сборку при первом
запуске):

```bash
./run.sh                 # игра
./run.sh game 42 180     # seed 42, карта 180
./run.sh client          # клиент мира: главное меню, сохранённые миры, Explore и Edit
./run.sh explore         # 3D-эксплорер Campfire
./run.sh engine-editor   # GUI модулей движка с GPU-viewport, без игры
./run.sh headless 200    # 200 суток без графики, с отчётом
./run.sh explain 5000    # таблица спроса и все жители на тике 5000
./run.sh validate
./run.sh test
```

### Клиент мира

`./run.sh client` (в CLion — **Campfire client**) — полноценный клиент:
главное меню → экран **Worlds** (список сохранений из `worlds/`: открыть в
Explore или Edit, создать новый мир — имя, тип, размер, сид — или удалить) →
загрузка → сам мир в одном из двух режимов, переключение — `Tab` или
переключатель в верхней панели.

- **Explore** — только мир: тонкая верхняя панель и строка подсказок, которая
  гаснет через несколько секунд (`F1` — вернуть). Отладочных панелей нет;
  `F3` показывает разработческие (полоса статуса, прогресс террейна).
- **Edit** — панель инструментов слева, строка состояния внизу (координаты и
  высота под курсором, горячие клавиши), Undo/Redo и Save в верхней панели,
  разметка кисти на земле, погода (дождь, снег, мокрая земля) выключена.
  Вкладки: **Terrain** — девять кистей в двух группах (D151): «руками» —
  Raise/Lower/Smooth/Flatten/Restore (Restore возвращает место к
  сгенерированной земле), «как природа» — Roughen/Scree/Erode/Channel,
  проходы генератора в следе кисти; клавиши `1`–`9`, `Alt` — в обратную
  сторону, `[` `]` — размер. **Objects** — вырубка по видам и посадка,
  **World shape** — регионы и слои генератора (D147); мир пересобирается
  после каждого мазка в фоне, и старый мир остаётся на экране, пока новый
  не готов. Мир собирается из генераций (D152): «Generate selected» —
  выделенные регионы своим прогоном, в свой размер; «Generate the whole world
  as one» — единая планета на весь мир. Добавленный регион пуст и ничего не
  пересчитывает; суша между прогонами соединяется краской материков. Широта
  мира — два ползунка в разделе WORLD.
  `Ctrl+Z`/`Ctrl+Shift+Z`, `Ctrl+S`. Каждая правка идёт через историю мира
  (D148) и сохраняется в корень рядом с раскладкой; раз в минуту — в фоне, при
  выходе — всегда.
- `Esc` — пауза: продолжить, сохранить, настройки графики, выйти в меню или из игры.

Проверка без рук — скриптовый проход по всем экранам со снимком каждого и
проверкой раскладки (наложения и вылеты текста за край):

```bash
campfire_client --client --client-tour /tmp/tour --headless 1600x1000
CAMPFIRE_UI_SCALE=2 campfire_client --client --client-tour /tmp/tour2x --headless 2880x1800
```

Сколько стоит открыть мир, по проходам (генерация, граф стока, климат,
пребейк страниц; дисковый кэш страниц выключен, если не `--disk`):

```bash
./cmake-build-relwithdebinfo/world_load_probe --regions 1
./cmake-build-relwithdebinfo/world_load_probe --grow     # мир растёт: остаётся ли старое как было
CAMPFIRE_LOAD_TRACE=1 campfire_client --client   # кадр за кадром, пока грузится земля
```

Или напрямую:

```bash
# посмотреть
./cmake-build-relwithdebinfo/campfire_client --seed 11 --map 140

# прогнать без графики и получить отчёт
./cmake-build-relwithdebinfo/sim_runner --days 200 --seed 11 --status-every 2400

# почему община делает именно это, на конкретном тике
./cmake-build-relwithdebinfo/sim_runner --days 60 --seed 3 --quiet --explain 5000

# проверить контент: все ли предметы достижимы голыми руками
./cmake-build-relwithdebinfo/content_validator

# редактор данных и интерфейса - отдельный клиент, мир не создаётся
./cmake-build-relwithdebinfo/campfire_editor --settings editor.json

# посмотреть на мир без игры: бесшовный террейн от метра до континента
./cmake-build-relwithdebinfo/campfire_client --explore
./cmake-build-relwithdebinfo/campfire_client --explore --at mountains --zoom 0.6 --shot /tmp/hills.png

# выписка «этнос → контент» (после правок в content/)
python3 tools/ethnos_table.py

# тесты
./cmake-build-relwithdebinfo/asr_tests
```

Внутренние CMake-цели `asr_client`/`asr_editor` и старые имена исполняемых файлов
оставлены как aliases для совместимости с инструментами и CLion. Новые имена —
`campfire_client` и `campfire_editor`. `run.sh` использует `CAMPFIRE_BUILD_DIR`
(старый `ASR_BUILD_DIR` также поддерживается).

## Модули и GUI движка

`campfire_engine_editor` — отдельный workspace камеры, terrain generation и
виртуальной геометрии. В нём работают Orbit/Free/Map, FOV, seed/relief,
фоновая генерация preview, выбор среза cluster DAG по экранной ошибке и wireframe.
Viewport рисует резидентную геометрию на GPU с depth buffer, аппаратным clipping и
матрицей общего модуля камеры. Это инспектор модулей, не редактор сохранённого мира.
Виджеты пока растеризуются программно в кэшируемый прозрачный слой и композятся на GPU;
движение камеры не перерисовывает неизменный интерфейс. Чтения GPU→CPU внутри кадра нет.
Запуск: `./run.sh engine-editor`; каталог сборки переопределяется через
`CAMPFIRE_ENGINE_EDITOR_BUILD_DIR`. Для снимка поддерживается `--shot FILE.png`.
Существующая GPU-сборка переиспользуется; новая GPU-сборка требует SDL_shadercross/DXC.
`--cpu-preview` выбирает прежний путь отрисовки. Для сборки вообще без DXC:
`CAMPFIRE_ENGINE_EDITOR_GPU=OFF ./run.sh engine-editor`.

Воспроизводимый orbit benchmark: `campfire_engine_editor --bench 240 --profile result.json`.
30 прогревочных кадров исключены; GPU-режим ожидает завершения каждого кадра.
Время включает CPU, GPU и ожидание, а не является чистым GPU timestamp.

Публичные CMake-цели: `Campfire::Camera`, `Campfire::Representation`,
`Campfire::Terrain`, `Campfire::VirtualGeometry`, `Campfire::VirtualGeometryGPU`,
`Campfire::Gui`, `Campfire::Render`, `Campfire::Viewport`, `Campfire::WorldStore`.
Первые четыре и `WorldStore` не требуют SDL или игровой симуляции. GPU-модули определены в
`src/engine/gpu_modules.cmake` и доступны с `ASR_BUILD_CLIENT=OFF`.
Перенесённые реализации находятся в `src/engine/`, игровые заголовки камеры и
terrain-полей оставлены как совместимые aliases.

Состав, проверки и границы реализации нового camera/LOD пути зафиксированы в коде,
тестах и `doc/DECISIONS.md`.

### Depth-aware impostors

`python3 tools/bake_impostor_depth.py` дополняет существующий
`assets/generated/scene_models` восьмиракурсным color/normal/depth atlas.
Нужны numpy/Pillow из среды импорта. Архивы исходников и геометрия SCM2 не меняются;
новый manifest публикуется только после успешного запекания всех моделей.
Старые каталоги без depth-atlas сохраняют прежний shader path.

`python3 tools/bake_impostor_depth.py --hemisphere` дополнительно создаёт 21 вид
на модель: 8 у горизонта, 8 на 45°, 4 на 70° и один сверху. Ресурсы добавляются
в отдельные диапазоны; material/grove/legacy-индексы не сдвигаются. Повторное
запекание переиспользует диапазоны и не увеличивает число слоёв.
После полного переимпорта исходной геометрии atlas следует запечь заново;
старую depth-карту нельзя переносить на изменённый mesh.

Математика декодирования и пересечения луча находится в модуле представлений
(`engine/render/impostor_depth.hpp`, `hemisphere_impostor.hpp` и одноимённые HLSL).
Depth-aware shader репроецирует UV и записывает восстановленную глубину.
Полусферический путь использует camera-facing quad и до четырёх соседних видов
с непрерывными весами, включая переход к полюсу. Селектор ограничивает ошибку
всех участвующих ракурсов; ниже полусферы остаётся геометрия.
Эти offline-кадры отдельных объектов также служат входом runtime-запекания кластеров.
Проверки, стоимость памяти и ограничения сведены в коде и `doc/DECISIONS.md`.

### Наземная флора и снимки для оценки вида

`python3 tools/make_foliage_cards.py` рисует карточки наземной флоры (короткая и
семенная трава, белые/жёлтые/лиловые/красные цветы, папоротник, сухая трава,
тростник, подлесок) и копии шести импортированных видов травы с заполненными
пустыми текселями для мипов; всё в `assets/generated/foliage_cards` (слои 6–15
массива карточек, `foliage.hlsl`). Без них рендерер подставляет траву.

`tools/look_shots.sh OUTDIR [WORLD] [SEED] [-- args]` — семь кадров (лес и луг
пешком, против солнца, общий план, река, сверху) **одним запуском** клиента
(`--shot-list`), со сторожем `LOOK_TIMEOUT`; `LOOK_GRAPHICS="a.json b.json"`
добавляет кадры пешком с другими настройками графики в тот же запуск. Для
оценки цвета — `-- --weather clear`. Числа по кадрам: `tools/look_metrics.py`,
`tools/look_palette.py` (оттенок земли и неба), `tools/look_hues.py`,
`tools/look_grid.py` (кадр текстовой сеткой).

### Runtime forest proxies

`Campfire::Impostors` — CPU baker и bounded residency cache без SDL/игры.
`Campfire::ImpostorsGPU` — фиксированный GPU-atlas и порционная публикация.
Кластеры 32 м собираются из реальных размещений растений и их hemisphere
color/normal/depth кадров: небольшие группы запекаются в промежуточные proxy,
затем в корень, без повторного обхода исходных мешей.

Один worker, восемь слотов, бюджет CPU-кэша результатов 16 MiB; за кадр
загружается один из 21 ракурсов (около 60 KiB). Объекты скрываются только после
полной публикации и принятия proxy общим селектором. Смена revision отменяет
право старого proxy на замену; slot reuse защищён submission fences и grace period.
Это первый runtime-уровень, не бесконечная многоуровневая иерархия всего леса.

Для A/B-проверок: `ASR_FOREST_PROXIES=0` отключает этот путь;
`ASR_SCENE_DEBUG=1` показывает bake/upload/submission счётчики.
Packed depth PNG читаются байтово-точно, минуя платформенную premultiplied-alpha
конверсию; ordinary colour-текстуры террейна не изменены. Подробности и текущие
ограничения отражены в `doc/DECISIONS.md`.

### Дальняя иерархия леса и туман дальности

Над 32 m proxy работает постоянная иерархия `Campfire::Impostors`
(`impostor_hierarchy.hpp`): 128 → 512 → 2048 m узлы, 4×4 детей на узел.
128 m узлы пекутся из детерминированного scatter региона (не из того, что сейчас
резидентно в placement), 512/2048 m — из запечённых детей в bounded CPU store
(96 MiB, LRU, помнит и пустые узлы). Ошибка узла измеряется при bake против
того, что реально показали бы дети (силуэт, выбор ракурса, dither), и монотонна
вверх по иерархии. Отбор: coarse→fine, узел и его потомки никогда не рисуются
вместе, дети остаются до полной резидентности родителя. GPU: 96 слотов 32²,
8 ракурсов за кадр, 2 фоновых bake-воркера (QoS utility на macOS).

Туман дальности: слайдер «Draw distance / fog» в статус-панели (мышь; `,` / `.`),
2–60 km, логарифмический. Туман прозрачен до 30 % дистанции и непрозрачен на ней;
цвет — небо вдоль того же луча (новый `SkyPass`), поэтому край мира растворяется,
а не обрывается. Та же дистанция ограничивает дальний лес и placement объектов.
Только perspective + Natural view. CLI: `--draw-distance METRES`, `--no-fog`;
`ASR_FAR_FOREST=0` отключает дальнюю иерархию.

### Настройки графики, scene view, небо и облака

В эксплорере `O` открывает окно графики (вкладки, выпадающие списки, чекбоксы,
ползунки; «Save» пишет `graphics.json` рядом с `editor.json`): пресет качества
(LOD-допуски, облака, дистанция), сглаживание (MSAA 4x / off — пересобирает
рендер), дистанция прорисовки/тумана, начало тумана, ширина переходов материалов
террейна, тени и их мягкость, 32 m прокси и дальний лес, солнце (высота, азимут,
сила), небо/ambient, экспозиция, скайбокс, поворот неба, объёмные облака
(качество 12/24/48 шагов, покрытие, плотность, высота).

`F` — scene view: камера всех решений (culling, LOD, импостеры, стриминг,
placement, тени) замораживается, живая камера становится свободной и только
рисует; замороженный фрустум виден жёлтым. `F` ещё раз возвращает к ней.
Для скриптов: `--scene-view-back METRES`, `--graphics-panel TAB`.

Небо: аналитическая атмосфера (Rayleigh+Mie) — она же цвет тумана — с перистым
куполом GoodSky из UE (`tools/export_ue_sky.py` → `tools/prepare_sky.py` →
`assets/generated/sky/cloud_dome.png`). Облака — объёмный слой в мировых
координатах (`cloud_field.hlsli`): виден в небе, между глазом и поверхностью
(горы в облаках, вид сверху) и отбрасывает тени; покрытие, толщина, база и
темнота следуют погоде (`--weather clear|rain|storm`), ветер их переносит.

## Мир на диске: история поверх генератора

Мир из файла (`--world-file worlds/world.json`, `./run.sh edit`) хранит свою
историю в корне рядом с раскладкой: `worlds/world/manifest.world` и
`worlds/world/delta/x_y.rN.wdelta` - по файлу на чанк 8×8 км. Генерированная
база не сохраняется никогда; сохраняется только то, что с миром случилось:
правки высоты (разрешённые по отсчётам 4 м), вырубленные сгенерированные объекты
(по стабильному имени: сид, стадия, домен решётки, страница 128 м, слот),
посаженное, вырубленные целиком страницы, клетки экологии. Одни и те же записи
делают редактор до игры и игра (`world::delta::WorldDelta`,
`src/game/world/world_delta.hpp`). Файлы чанков - блоки zstd с заголовком и
хешами (`src/engine/world_store`, `Campfire::WorldStore`); манифест заменяется
последним и атомарно, поэтому сбой при сохранении оставляет предыдущее
состояние целым. Сохранение идёт на своём потоке раз в 20 секунд и на выходе.

```bash
./run.sh world-inspect                     # что лежит в worlds/world
./run.sh world-inspect worlds/world --ops  # и каждая запись журналов
```

Вскопанная земля - та, что нарисована: страницы террейна пекутся поверх правок
высоты, их дисковый кэш кладёт страницы над правками рядом со страницами
генератора (`x_y-g<отпечаток>.bin`), а после новой копки резидентные страницы,
меши и деревья над ней переделываются на месте - старая земля видна, пока не
готова новая, дыр нет. Проба живого пути - копка через ту же дельту, без
сохранения:

```bash
campfire_client --explore --world 64 --at "open country" --zoom 1 \
    --dig 28504,20736,120,-30 --headless 1280x800 --shot /tmp/dig.png
```

Вода, тени, дальний лес и симуляция о копке пока не знают. Инструменты правки -
в клиенте мира (`./run.sh client`, режим Edit). Решения и границы - D148, D149 и
D150 в `doc/DECISIONS.md`.

## Внешний профайлер

`tools/campfire_profiler.py` — **отдельная тулза**, не библиотека движка.
Она подключается к PID или запускает исполняемый файл через macOS Instruments.
В коде движка не нужны Tracy-зоны, `printf`, reflection или compiler hooks.
Нужны macOS и Xcode; debug symbols улучшают имена стеков, но не являются инструментацией.

```sh
python3 tools/campfire_profiler.py processes
python3 tools/campfire_profiler.py record --pid 12345 --mode cpu --seconds 10
python3 tools/campfire_profiler.py record --mode memory --seconds 10 --debug-copy \
  --launch ./cmake-build-relwithdebinfo/campfire_client -- --explore
```

Режимы: `cpu` (семплирование стеков), `memory` (аллокации), `gpu` (Metal),
`system` (потоки/ожидания), `counters` (аппаратные счётчики, если доступны на машине).
Запись сохраняется в новой папке `.cache/profiles/`: `capture.trace` открывается
в Instruments. CPU-режим дополнительно создаёт локальные `report.html` и `summary.json`.
`--open` открывает Instruments после записи. Ничего не отправляется в облако.

Семплы CPU — статистика, не точное время каждой функции и не GPU-время.
История аллокаций до подключения не восстанавливается: для неё нужен режим `--launch`.
Если macOS не разрешает Allocations подключиться, `--debug-copy` создаёт в папке
записи отдельную копию с debug-подписью. Основной бинарник и исходники не изменяются;
SIP и системные настройки безопасности не отключаются.
Instruments может завершить запущенный через `--launch` процесс по лимиту записи;
для уже работающего клиента без такого завершения используйте `--pid`.
Записанный trace при ненулевом коде xctrace отмечается предупреждением, а не скрывается.
Ограничения доступа/счётчиков записываются как ошибки, а не как нулевые результаты.
Старый UE-проект-донор **AncientSettlement** и исторические документы не переименованы.

## Управление в клиенте

| Клавиша | Действие |
| --- | --- |
| `пробел` | пауза / вернуться к прежней скорости |
| `1` `2` `3` `4` `5` | скорость x1, x2, x5, x10, x100 |
| `-` `+` | шаг по лестнице скоростей |
| `z` / `j` / `o` | оверлей областей / целей работ / выключить |
| `e` | режим рисования областей |
| `p` | панель приоритетов работ |
| `wasd`, стрелки | камера, колесо — зум |
| клик по чему угодно | карточка объекта справа |
| повторный клик по тому же гексу | следующий объект под курсором: житель → овца → строение → дерево → куча → земля |
| правый клик | снять выделение |
| `h` | спрятать панель управления |

Отъехав камерой за пределы карты, попадаешь на карту страны — 368 × 368 км, на
ней **пятнадцать общин, и каждая начинает теми же 24 людьми в то же утро, что и
ты** (D94). Все они живут по-настоящему и всё время, а не только когда на них
смотрят (D95):

| Действие | Что делает |
| --- | --- |
| клик по поселению | карточка: народ, чем кормит их земля, сколько живых, рождений, смертей |
| повторный клик или `enter` | смотреть за ними: карта, панели и инспектор переключаются на их общину |
| `esc` | вернуться к своим (а из своей долины — выйти из игры) |

Без клиента то же самое делает `sim_runner --all`: прогоняет все общины разом и
печатает таблицу — кто на какой земле, сколько живых, рождений, смертей, построек.

В режиме рисования областей: `[` `]` — тип области, `m` — режим (разрешено,
предпочтительно, высокий приоритет, запрещено), `,` `.` — размер кисти, левое
перетаскивание рисует, правое стирает. Стирается только нарисованное игроком:
то, что община разметила себе сама, кистью не убрать.

### Что даёт уровень навыка

Право попробовать даёт знание способа, а не уровень. Любой, кто знает способ,
делает вещь с первого дня — просто медленно и хуже. Уровень покупает скорость и
качество: у инструмента и одежды есть `quality` от 0.75 до 1.5, взятое из руки
мастера, и оно множит эффективность топора и тепло плаща. Требование к уровню
существует как отдельное условие и не задано ни у одного определения в `content/`
— оно для исключительного (зиккурат, расшитое облачение), чего пока нет. За этим
следит тест.

### Гексы и области

Клетка — остроконечный гекс шириной один метр. Все шесть соседей равноудалены,
поэтому расстояние, стоимость пути и граница области считаются без поправок на
диагональ, а нарисованная от руки область выглядит областью, а не лесенкой.

Угодья община размечает себе сама, читая землю вокруг очага: поселение, склад,
линия укреплений, делянка леса, каменоломня, охотничьи угодья, пашня и пастбище.
Центр каждого выбирается по плотности того, ради чего область нужна, с поправкой
на удалённость от дома, — поэтому поселение оказывается рядом со своими работами.
Игрок рисует поверх свои области; община их не трогает.

Голубой контур `HOME` виден постоянно: это домашний центр радиуса 12, где община
строится, но не запрет выхода. Рабочие области могут лежать дальше, а двое
разведчиков расширяют известную землю. Пешка снаружи HOME получает тёплый маркер,
поэтому массовый выход сразу отличим от жизни внутри поселения.

Приоритеты работ (`p`) — множитель на оценку планировщика, а не приказ: они не
делают выполнимой работу без инструмента, материала или маршрута.

### RTS-здания и жизнь внутри них

Жильё моделируется целым зданием — без отдельных кроватей и мебели. У него есть
footprint, стоимость, вместимость, тепло и комфорт; комфорт ускоряет восстановление
сна. Общая/эгейская линейка: `lean_to` → `hut` → `timber_house`, месопотамская:
`reed_shelter` → `reed_hut` → `mudbrick_house`. Семьи детерминированно получают
завершённый дом по вместимости и комфорту; он показан в карточке персонажа.

Уставший человек физически идёт на origin своего дома и спит там. В доме есть
маленький food-only pantry на 1–3 физических партии: hauler заполняет его раньше
общего амбара. Вечером голодный возвращается к домашней партии и ест внутри;
днём у далёкой работы выбирает ближайшую еду без бессмысленного круга. Если pantry
пуст, личная порция переносится из склада домой как `Carried`. Критически голодный
ест ближайшую или уже несомую порцию сразу. Еда не телепортируется.

Поиск еды и воды начинается на 65%, потому что удовлетворение нужды теперь
включает физическую дорогу. Скорость расхода потребностей не менялась.

`campfire` — стартовый огонь, а не мебель-печь для всей пищевой цепочки. Хлеб и
другая печная продукция требуют radius-1 производственное здание: `bakery` или
культурный вариант `mudbrick_bakery`. Склады остаются отдельными зданиями:
`store_pit`, `granary`, `mudbrick_granary`.

Кликается всё. Житель показывает потребности полосами, текущее занятие или
причину простоя, навыки, черты, известные способы и семью. Строение — стадию,
доставленные материалы против нужных, свойства и содержимое склада. Природный
объект — что с него получат, сколько это работы, каким инструментом, в какой
сезон и когда отрастёт. Куча — сколько в ней, чья она, сколько осталось до
порчи, во что она идёт дальше и сколько её сейчас хочет община. Пустая земля —
рельеф, плодородие, загрязнение и накрывающие тайл зоны. Клик никогда не
возвращает пустоту: под всем лежит тайл.

Гекс — один метр. Земля рисуется в плоской top-down проекции без перспективного
сжатия и псевдообъёмных стенок. Объекты сортируются по точке опоры, поэтому
перекрывают друг друга естественно. Поселенцы собираются из тела, головы и одежды
из source sheet `assets/sprites/3ab02eb8-2e60-4e4c-8926-d12156ce5fea.png` по
нарезке `pawn_sheet_v2_manifest.json`: юг, восток, север и зеркальный запад.
Надетые `linen_tunic` и `loincloth` добавляют независимые слои tunic/skirt и могут быть
видны одновременно; стартовый pawn состоит только из body+head и действительно
голый. Возраст меняет масштаб. Между авторитетными fixed-point позициями
симуляции клиент двигает тела плавно собственной float-позицией, не влияющей на
детерминизм.

Первые варианты из `assets/sprites/props` уже заменяют placeholders деревьев,
кустов, диких растений, камней, дичи, овец, жилья и очагов. RGB-листы получают
прозрачность и tight trim один раз при загрузке; mapping записан в
`assets/sprites/props/manifest.json`.

**3D-эксплорер (`--explore`) с 2026-09-26 использует подготовленные ресурсы
AncientSettlement UE:** бук и ель с восстановленной assembly-кроной, куст, камень,
гриб, брёвна, пни, ветки, MWAM-траву и шесть поверхностей
MW Landscape. Активный каталог — `assets/generated/scene_models/`, его маркер
`.ue-imported` защищает набор от перезаписи старым импортом. Прежний архив
Nature MegaKit и заменённые карты удалены. Остальные 2D-спрайты, персонажи и UI
сохранены. Состояние импорта и ассетов описано в `doc/environment_assets_2026-10-02.md`,
превью ресурсов — `assets/generated/ue_foliage_preview.png`.
Подлесок загущён, палитровый тинт земли отключён; освещение, намокание и снег сохранены.

`walk_tiles_per_hour = 55` означает 55 метров за игровой час: один tick может
израсходовать бюджет на несколько гексов, учитывая рельеф, состояние тела и груз.
Работа и потребности используют ту же базу `ticks_per_hour`, поэтому дорога,
рецепты, голод, усталость и календарь измеряются согласованно.

Известная земля ограничивает обычную работу: община видит вокруг очага 20 гексов
и работает в пределах 55 от себя, а границу известного расширяют двое
разведчиков — не вся община разом.

Ускорение не меняет сам тик — оно только просит их больше в секунду, поэтому
партия на x100 побитово совпадает с той же партией на x1 и с headless-прогоном
того же seed. Базовые 0.5 тика/с дают 8 реальных минут на игровые сутки при x1;
x10 соответствует прежнему x1, а x100 — прежнему x10 (50 тиков/с). Запас по
производительности большой: симуляция даёт около 44 000 тиков в секунду.
Лестница скоростей — одна таблица
`kSpeedLadder` в `src/ui/overlay.hpp`, добавить ступень стоит одну строку.

## Устройство

Разделение модулей взято из §11 GDD.

| Каталог | Что это |
| --- | --- |
| `src/core` | Fixed-point, детерминированный ГПСЧ, типизированные идентификаторы, календарь. Никаких игровых понятий. |
| `src/content` | Декларативные определения и загрузчик. Валидатор ацикличности стартовой цепочки. |
| `src/generation` | Генерация локальной карты: рельеф, река с бродами, природные объекты, выбор очага. |
| `src/world` | Поверхность мира: поле высот в мировых координатах, меш чанка, обрывы. Сетка чанков - хранение и стриминг, а не границы мира (D113). |
| `src/simulation` | Мир, жители, потребности, планировщик работ, исполнение, демография, пашня, скот, области, отчёт. Headless. |
| `src/client`, `src/ui` | SDL3-рендер и HUD. Симуляция о них не знает. |
| `sim_runner` | Автономные прогоны, отчёт, дамп решений. |
| `src/editor` | `asr_editor`: редактор данных и темы отдельным клиентом, свои настройки в `editor.json`. |
| `tools` | Валидатор контента. |
| `tests` | 51 проверка: арифметика, гексовая геометрия, детерминизм, поиск пути, контент, поведение общины, инспектор. |
| `content/` | Весь игровой контент в JSON. |

### Что гарантируется

- **Детерминизм.** Симуляция не содержит плавающей точки. Два мира из одного
  seed совпадают по контрольной сумме на каждом тике — это проверяется тестом,
  а `sim_runner` печатает сумму в строке состояния.
- **Ничто не возникает неявно** (§2.2). Каждое преобразование — рецепт с
  исполнителем, временем, местом, входами и, где нужно, инструментом.
- **Нулевая цепочка** (§7). `content_validator` доказывает, что от действий
  голыми руками достижим каждый предмет и каждое строение, без циклических
  зависимостей вида «для инструмента нужен верстак, для верстака — инструмент».
- **Простой объясняет себя.** Каждый бездействующий житель называет причину, и
  она попадает в отчёт: нет работы, нет инструмента, нет материалов, цель
  недостижима, не в состоянии работать.

### Как выглядит рабочий прогон

```
$ ./build/sim_runner --days 200 --seed 11 --map 140 --status-every 2880
y0 spring d13 | pop 10 | food 116 | flock 7  | working 10/10
y0 summer d10 | pop 12 | food 320 | flock 7  | working 10/12
y0 autumn d7  | pop 12 | food 383 | flock 9  | working  9/12
y0 winter d4  | pop 12 | food 501 | flock 9  | working 12/12
```

Община переживает зимы за счёт зерна, сжатого со своего поля и обмолоченного
осенью, и это возникает из модели спроса, а не из сценария. На лучших seed'ах она
доживает до десятого года; на худших гибнет на третий-пятый, обычно поздней зимой,
и отчёт называет причину.

## Что дальше

Ближайшее по GDD: вода как переносимый ресурс (в том числе для скота и полей),
ранения и болезни, отношения и воспоминания, затем политический контур — совет
глав семей, законы и правитель как управляемый персонаж. Полный список известных
пробелов — в конце `doc/DECISIONS.md`.

Самое незрелое место по-прежнему баланс: община выживает годами, но в итоге гибнет
поздней зимой. Все числа лежат в `content/`, не в коде, и `sim_runner --explain`
показывает таблицу спроса, по которой видно, почему она выбрала именно это.
