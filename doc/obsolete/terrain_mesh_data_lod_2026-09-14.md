# Terrain: LOD геометрии отдельно от качества данных

## Изменение

Прежние пороги сетки 1.75 / 2.5 / 1 px включали меш LOD0 ещё тогда,
когда объект ростом 1.7 м был меньше пикселя. Новые пороги в `LodPolicy`:
целевой размер ребра 96 px, уточнение при >128 px, огрубление при <48 px.
Это стартовая визуальная настройка, а не измеренная допустимая ошибка рельефа.
Предикаты ошибки высоты сохранены, но текущий планировщик передаёт им ноль:
адаптация по фактической ошибке поверхности этой правкой не реализована.

При приближении переход 8 -> 4 м происходит при масштабе >16 px/м:
человек 1.7 м имеет около 27 px до проекционного сокращения. При удалении
4 -> 8 м происходит ниже 12 px/м, около 20 px для такого же объекта.
При первом кадре используется промежуточный целевой порог. Гистерезис
и существующий геометрический морфинг сохраняются.

В ортографической камере масштаб берётся из матрицы проекции и размера
viewport, без прежнего фиксированного коэффициента 0.25 для изометрии.
В перспективе решение принимается отдельно для каждого блока по ближайшей
глубине его консервативного AABB, FOV и viewport; дальняя земля не получает
LOD0 только из-за близкого фокуса. Вклад границ блока остаётся консервативным.

Новые пороги используются в page-renderer. Legacy CPU-меши сохраняют явные
пороги 1.75 / 2.5 / 1 px: у них материалы интерполируются из вершин, а не из
независимого поля в пикселях. Их плотность и шкала морфинга не изменяются.

## Данные

`DataLodPolicy` регулируется отдельно от `LodPolicy`; активный GPU renderer
передаёт `kRenderDataLodPolicy{1}` планировщику. Наличие H4 в памяти само
по себе не требует разбиения меша. Базовый профиль `{0}` остаётся доступен
CPU/низкобюджетным потребителям. Число дополнительных уровней ограничено
диапазоном 0..2, чтобы мировой корень LOD6 продолжал использовать H64.

| LOD меша | Шаг меша | Данные GPU renderer |
| --- | --- | --- |
| 0 | 4 м | H4 |
| 1 | 8 м | H4 |
| 2 | 16 м | H8 |
| 3 | 32 м | H16 |
| 4 | 64 м | H16 |
| 5 | 128 м | H64 |
| 6 | 256 м | H64 |

Это отдельный профиль качества данных относительно геометрии, а не второе
независимое дерево с собственными экранными порогами. RAM-кеш, формат страниц,
фоновая подготовка и постоянные H16/H64 не изменены.

Блок `TerrainPlan` явно хранит `dataLevel` и `parentDataLevel` (номера страниц
0/1/2/4); `tile.lod` задаёт только геометрию. GPU переводит номера страниц
в слои атласов 0/1/2/3, не восстанавливает их из LOD меша. Уже существующие
шейдеры читают мелкие поля для материала/нормалей в пикселях независимо от
сетки, а вершины используют те же поля на геометрической решётке.

Зависимости включают выбранные поля ребёнка и родителя, углы родительского
треугольника и halo нормалей. Admission H4/H8 теперь определяется выбранными
данными, а не условием `parent.lod <= 2`. Родитель остаётся покрытием до
готовности всей семьи; страницы не освобождаются до обратного морфинга
и завершения GPU submissions.

## Отсев воды до отправки на GPU

Воркер при `packHeightPage()` проверяет фактически упакованные каналы покрытия
и типа воды во всех семплах, включая padding. Только если покрытие, river и
lake везде нулевые, страница доказанно сухая для текущего `WaterPS`: его
океанская ветка безусловно отсекает такой фрагмент независимо от волн/погоды.
Одного нулевого покрытия недостаточно: inland-ветка вблизи использует глубину.

Доказательство публикуется через `HeightPageAtlas` вместе со всеми GPU-полями.
Неудачная загрузка, предварительный слот, вытеснение и отсутствие данных
не могут выдать доказательство сухости. CPU-план получает копию `dryPages`
только после публикации таблицы. Для блока проверяются оба набора данных,
родительские углы и halo; отсутствующая океанская страница считается водой,
поскольку шейдер возвращает для неё покрытие 1.

Флаг сохраняется для всего retained coverage. `WaterPass::anything()` и
`collect()` пропускают доказанно сухие блоки без повторного анализа семплов
в потоке рендера. Морская подложка и legacy-путь сохранены. Проверка намеренно
консервативная: вода в соседней части страницы может оставить лишний draw.
Это не occlusion culling и не потриангольное отсечение.

`ASR_TERRAIN_PROFILE=1` выводит `ground-triangles`, `water-blocks`,
`water-skipped`, `water-triangles` для page grids. Счётчик земли включает
включённые юбки; водный — только поверхность. Морская подложка, растительность
и UI в эти числа не входят. Заголовок окна и логи теперь называют шаг меша
`mesh edge`, а не шагом семплов данных.

## Границы изменения

- Решётка остаётся 64x64 ячейки: минимальный блок LOD0 всё ещё 256x256 м.
  Уменьшена область выбора этого уровня по экранному масштабу, не размер блока.
- Данные H4 под сеткой 8 м сохраняют поле высот и пиксельное оформление,
  но не воспроизводят геометрический силуэт каждого 4-метрового отсчёта.
- Более мелкая сетка, LOD моделей персонажей и независимое
  переключение полей без морфинга геометрии сюда не входят.

## Проверки

`asr_terrain_tests` содержит регрессии масштаба человека, FOV/viewport/depth,
гистерезиса, H4 под LOD1, halo/pins, обратного морфинга, потери страницы без
дыры и admission H8 уже на родителе LOD3. GPU readback-тест
`height_atlas_gpu_shared_grid_reads_heights_and_morphs_to_parent_triangles`
уже проверяет H4/H8 на сетке 8 м, поле пиксельного оформления и плоскость
родительского треугольника. Дополнительная CPU-регрессия сохраняет одинаковый
меш 16 м при трёх профилях данных: H16, H8 и H4.
