# Библиотека реальных форм рельефа

Библиотека подключена к **гибридному генератору новых миров**: реальные формы
сочетаются с региональным размещением, процедурным сопряжением и фрактальными
деталями. Исходные файлы импортёра не изменяются. Старые сохранения без гибридного
слоя читаются без автоматического добавления новых гор.

## Состав и расположение

- Авторский список: `content/config/terrain_references.json` — 64 географически
  разных участка, восемь визуальных семейств по восемь участков.
- Импортёр: `tools/fetch_terrain_references.py`.
- Зависимости Python 3.10+: `tools/terrain_references_requirements.txt`.
- Подготовленная библиотека: `assets/generated/terrain_references/`.
- Оригинальные PNG-тайлы: `.cache/terrain_reference_tiles/`.
- Общая таблица превью: `assets/generated/terrain_references/contact_sheet.jpg`.
- Состав реально готовой библиотеки: `index.json`; ошибки/время импорта:
  `download_report.json` в том же каталоге. Неполная загрузка не объявляется полной.

Семейства: альпийские пики, ледниковые нагорья, вулканические массивы, плато и
каньоны, складчатые хребты, сухие горные массивы, старые массивы, скальные башни
и карст. Это метки для выбора визуального характера, не строгая геологическая
классификация. Подбор координат ещё не заменяет художественную проверку каждой
формы; наличие 64 участков само по себе не гарантирует неповторяемость генерации.

## Формат каждого участка

Каталог `<id>/` содержит:

- `height.h16`: 1024×1024 unsigned 16-bit little-endian, построчно, **без заголовка**;
- `height.png`: те же 16-битные значения для просмотра/редактирования; не RGB-снимок;
- `metadata.json`: начало и масштаб высот, координаты, проекция, размеры, источники
  каждого исходного тайла и SHA-256;
- `preview.png`: уменьшенная затенённая картинка, **только для просмотра**.

Восстановление физической высоты: `height_offset_metres + stored * height_scale_metres`.
Диапазон каждой карты записан явно; нормализация не означает потери исходного
масштаба гор. Все 64 необжатых массива высот вместе занимают 128 МиБ. PNG-копии,
метаданные, исходные тайлы и Python-окружение занимают дополнительное место.

Сетка каждого участка имеет шаг **8 м** в локальной азимутальной равнопромежуточной
проекции WGS84, центр — указанная точка. Строки идут с севера на юг, столбцы —
с запада на восток. Между крайними отсчётами 8184 м (1023 интервала по 8 м).
Метрический размер не принимается равным пикселям Web Mercator: перепроекция
выполняется через PROJ, что существенно для Норвегии и других высоких широт.

**8 м — шаг подготовленной сетки, не обещание исходной точности DEM.** У разных
регионов разные первичные источники, а тайлы могут содержать интерполированные
значения или поверхность снега/растительности. Увеличение разрешения результата
не создаёт новых измерений. Поле `source_tile_grid_metres_at_centre` описывает
лишь сетку исходных terrain-тайлов; ограничения первичного DEM см. у поставщиков.

## Источник и преобразования

Источник: Mapzen Terrain Tiles / AWS Open Data:
https://registry.opendata.aws/terrain-tiles/

Импортёр получает RGB PNG в формате **Terrarium**, декодирует реальные высоты
как `R*256 + G + B/256 - 32768` **до** интерполяции. Затем сшивает исходные тайлы,
выполняет билинейную выборку на метрической сетке и квантует результат в uint16.
Выбирается уровень тайлов, близкий к целевому шагу, не выше z14. Экспорт экрана
Heightmapper с 256 уровнями серого здесь не используется.

HTTP-запросы ограничены 8 параллельными обработчиками максимум, имеют таймауты
и повторы. Записи атомарные. Повторный запуск использует оригинальные тайлы и
уже завершённые результаты с совпадающими параметрами и SHA-256. Пропуски высот
не заполняются выдуманными значениями; такие участки попадают в отчёт ошибок.
Для наземных образцов также отбраковываются неправдоподобные высоты вне
диапазона −500…9000 м (при необходимости задаётся индивидуальный диапазон).
При первой загрузке Fitz Roy, Blyde и Wadi Mujib были заменены: в исходных
тайлах нашлись многокилометровые отрицательные выбросы. Причины сохранены в
`rejected_candidates` авторского списка, отклонённые результаты убраны из
библиотеки в `.cache/terrain_reference_rejected/`. Etna и Velebit также заменены
из-за пропусков исходных высот; вместо них взяты Shasta и Sella. Это проверка грубых ошибок,
не гарантия отсутствия всех артефактов первичных DEM.

## Воспроизведение

Создано отдельное окружение `.cache/terrain-reference-tools/`; системный Python
не изменяется. Запуск его `bin/python` с `tools/fetch_terrain_references.py`
подготавливает полный список. `--only` принимает ID участков для повторной
обработки, `--workers` задаёт число обработчиков, `--output` и `--cache` меняют
каталоги. Для другой машины потребуется Python 3.10+ и установка зависимостей
из указанного requirements-файла. CLion без настроенного Python SDK может
подсвечивать даже импорты стандартной библиотеки; импортёр запускается своим
изолированным интерпретатором.

Список и импортёр хранятся в Git; `.cache/` и `assets/generated/` уже исключены
правилами проекта. Бинарники не попадут в репозиторий автоматически: при сборке
дистрибутива библиотеку надо воспроизвести или включить отдельно вместе с
атрибуцией. Не удалять её как ненужный кэш, если требуется сохранить скачанные
образцы для работы без сети.

## Runtime: гибридный генератор

- Модуль: `src/game/generation/hybrid_terrain.{hpp,cpp}`.
- `WorldMapParams::hybridTerrain` по умолчанию включён; `false` оставляет старый
  синтез. `terrainReferenceRoot` задаёт явный каталог библиотеки. Если он пуст,
  сначала учитывается `ASR_TERRAIN_REFERENCE_DIR`, затем расположение ресурсов
  относительно рабочего каталога и исходников сборки.
- Размещение детерминировано по seed, параметрам и содержимому библиотеки.
  В одном мире используется подходящая выборка, **не все 64 карты сразу**.
  Тип выбирается по высоте, геологии и приближённым условиям региона; это
  художественная эвристика, а не полноценная симуляция геоморфологии.
- `.h16` декодируется явно как little-endian, с проверкой размеров, формата,
  направления строк и численного диапазона метаданных. В метрах учитываются
  offset/scale; внешний высотный уровень образца заменяется местным основанием.
- Форма поворачивается, умеренно деформируется и сопрягается с окружением через
  круглую маску с плавным затуханием на границе. Квадраты DEM не укладываются
  плиткой. Горный профиль строится по каркасу: три уровня
  ветвления, разные направления по регионам, плавные склоны и подъём в узлах.
  Реальный DEM даёт 80% формы, каркас — 20%; без DEM работает один каркас.
- Горные DEM проходят метрический Gaussian-фильтр (σ около 96 м исходника),
  сохраняющий 15% высокочастотной разности. Дополнительная шумовая деталь —
  максимум 2 м у высоких гребней с затуханием к подножию. Каньоны, скальные башни
  и вулканические кратеры этим горным фильтром не сглаживаются.
- Региональные формы заранее запекаются в **32-метровые signed-decimetre поля**.
  Это осознанное ограничение первой реализации: она не переносит всю 8-метровую
  детализацию исходника. Билинейный runtime-семплинг не читает диск; ниже этого
  масштаба работают существующие визуальные residual-слои.
- Крупная составляющая меняет ячейки до климата и priority flood. `HeightField`
  добавляет только разность точной формы и её макропредставления, ограниченную
  ±450 м. Общая географическая деформация согласует высоты, грунты и покров;
  существующий GraphCarver сохраняет владение руслами и уровнями воды.
- Вулканы имеют процедурное основание, конус и кальдеру с DEM-асимметрией склонов.
  Островные формы размещаются только на подходящем полностью морском участке;
  если места нет, остров не создаётся принудительно. Это не симуляция извержений:
  динамической лавы и горячих источников пока нет.
- Вулканическая порода и возраст поверхности влияют на почвы, камень/пепельный
  грунт и растительность, но не заменяют климатический биом: старые влажные склоны
  могут оставаться лесными, высокие — снежными.
- Отсутствующие/повреждённые образцы дают аналитический резервный вариант.
  Причины сохраняются в `HybridTerrain::diagnostics` и выводятся диагностикой.
  Изменение библиотеки меняет входные данные нового мира; уже запечённый мир
  от неё не зависит. Декодированные исходники кешируются на время процесса.
- Формы сохраняются в экспорте карты и игровых сохранениях, включая исходный
  fingerprint. Загрузка использует снимок до пересчёта климата/рек и не требует
  DEM-библиотеку. Версии, размеры и контрольная сумма запечённых данных проверяются.
  Fingerprint включён в идентичность гидрологии и страниц; версия генерации
  persistent pages — 5, версия графа гидрологии — 7.

### Проверка

Собрать `asr_terrain_tests`, `asr_tests` и `hybrid_terrain_probe` через CMake.
`asr_terrain_tests hybrid` проверяет импорт, острова, fallback, сохранения,
границы, совпадение worker/LOD-высот и высотный диапазон. Дополнительный тест
игрового сохранения — `asr_tests hybrid_game_save`.

Пример диагностического прогона из корня проекта:

```sh
./build/hybrid_terrain_probe --seed 42 --cells 96 --validate-library \
  --svg assets/generated/terrain_references/hybrid_world_42.svg
```

JSON-отчёт содержит выбранные формы, координаты, размер запечённых данных,
время генерации, предупреждения и число высот вне допустимого диапазона.
SVG — диагностическая карта поля высот с метками форм, **не скриншот рендера**.
`--legacy` позволяет сравнить с предыдущим синтезом; `--references DIR` —
проверить другую библиотеку или явный резервный режим при отсутствующем каталоге.

`mountain_shape_probe <preview.svg>` измеряет один и тот же горный участок
seed 42 (32-метровая сетка, центр 35640/31320 м), выводит локальные максимумы и
мелкую кривизну. Сравнение до/после и ограничения метрик:
[mountain_ridges_2026-09-15.md](mountain_ridges_2026-09-15.md).

## Лицензии и атрибуция

У агрегированного набора нет единой декларации «всё CC0». Вместе с библиотекой
сохранены неизменённые документы поставщика:

- `ATTRIBUTION_UPSTREAM.md` — требования и рекомендуемые формулировки;
- `DATA_SOURCES_UPSTREAM.md` — описание первичных DEM и ссылки на их условия.

Оригинал требований: https://github.com/tilezen/joerd/blob/master/docs/attribution.md

Используются, в частности, высоты USGS, европейские EU-DEM/Copernicus, данные
Kartverket, LINZ и других поставщиков, перечисленных в исходной документации.
Каждый результат содержит ссылки на скачанные terrain-тайлы, но не выдаёт
географическое предположение за точное определение первичного поставщика
каждого пикселя. При распространении нужно сохранить применимую атрибуцию и
указать произведённые изменения: вырезка, перепроекция, интерполяция, квантование.
Основной `CREDITS.md` автоматически генерируется другим инструментом; эта
атрибуция ведётся отдельно, чтобы тот инструмент её не затёр.
