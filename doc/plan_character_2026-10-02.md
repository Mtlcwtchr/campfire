# План: управление персонажем мышью на карте (2026-10-02)

Сейчас персонажем управляют только WASD от 1-го и 3-го лица (D177). В виде карты
нужно идти туда, куда кликнули, обходя то, что не пройти.

## Что для этого нужно

1. **Проходимость по чанкам.** Навмеш строится по требованию для чанков вокруг
   персонажа, а не для мира: мир — тысячи квадратных километров. На чанк 128 м
   (страница расстановки, `kPlacementPageMetres`) берётся сетка высот 1 м из
   страниц террейна и отмечается, где не пройти:
   - склон круче 1.2, тот же порог, что у `CharacterController`;
   - вода глубже 0.6 м (`HydrologyBuilder`, озёра и реки);
   - стволы деревьев и крупные камни из расстановки: круги по `Object` с радиусом
     модели.
2. **Сетка → навмеш.** Как в Recast: вокселизация уже готова (сетка высот),
   эрозия на радиус персонажа (0.35 м), регионы водоразделом, контуры, полигоны.
   Либо, на первое время, поиск прямо по сетке (A* по 8 соседям с подтяжкой пути
   string pulling). На чанк 128×128 = 16 тыс. клеток, это ~0.5 мс на чанк.
3. **Склейка чанков.** Края чанков сшиваются по общим клеткам. Путь ищется на
   графе чанков (иерархически), внутри чанка — по сетке.
4. **Стоимость кадра.** Строить в фоне, задачами пула потоков (не `std::async`,
   см. D171), не больше 2–4 чанков на кадр. Перестраивать только то, что тронули
   правки мира: ревизии `EditLayer` и `WorldDelta`. Кэш LRU по памяти.
5. **Клик.** Луч из `Camera::screenRay` до пересечения с землёй (как
   `worldOfScreenAtHeight`, два прохода). Путь до точки, `CharacterController`
   получает следующую точку пути как направление «вперёд». Новый клик меняет цель;
   клик в непроходимое — ближайшая проходимая клетка.
6. **Показ.** Маркер цели и линия пути через `HighlightPass` (линии поверх мира).

## Порядок

Сетка проходимости на одном чанке → A* по сетке → путь в контроллер → клик на карте
→ склейка чанков → фоновая сборка и кэш → навмеш полигонами, если сетка окажется
дорогой.
