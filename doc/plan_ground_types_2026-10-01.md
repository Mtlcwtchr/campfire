# План: категории террейна и биомы слоёв как часть движка — id из control-карт, всё остальное в конфиге

Состояние на 2026-10-01: control-карты континента собраны (D164, D165), в источнике лежит
`ground` (categorical u8, 256 м) с легендой `ground_legend.json`; шесть новых текстур
скачаны и упакованы (слои 16–21 каталога), к рендереру **не подключены**. Генератор пока
читает только `moisture_bias` и `erosion_strength`.

**Цель.** id земли на control-карте — это **категория террейна**. Карта больше ничего не
говорит о виде земли: всё, чем категория отличается от соседней, выбирается *внутри неё*
в данных:

- базовые почвы и их шумы;
- камень на склонах;
- наземный фолиаж или его отсутствие;
- лес: фертильность, вид, густота, поляны, подлесок;
- декорации: брёвна, пни, ветки, камни — их наборы и густота;
- включённые наборы декалей;
- тип водоёмов (в Пустошах — зелёная гнилая вода);
- значения control-каналов по умолчанию.

Лес, вода и декор — **свои control-слои со своими биомами**, настраиваемыми так же
отдельно: биом леса — это какие деревья, кустарники, подлесок, текстуры лесной подстилки
и мелкий декор (ветки, шишки, грибы, брёвна, пни) и с какой густотой. id 0 в таком слое —
«как велит категория земли», поэтому рисовать лес отдельно нужно только там, где он не
такой, как обычно для этой земли (см. «Control-слои и их биомы»).

Перекрасил рукой id — земля, лес, вода, декорации и декали этой клетки становятся
другими. Непрерывные control-каналы (влажность, лес, горы, эрозия) остаются ручками
*внутри* категории: двигают густоту леса, сырость, сколько камня, но не меняют, какой
это лес и какие тут декали. Детали (экземпляры декалей и декораций) выводятся процедурно
и не хранятся; хранятся отдельно только ручные правки деталей.

## Разделение: что движок, что контент

| Слой | Где | Что |
|---|---|---|
| Ключи на местности | источник мира (`engine/world_source`) | categorical u8, 256 м, только суша: `ground` (категория), `forest`, `water`, `decor` (биомы слоёв, 0 — по категории); **легенда каждого слоя в манифесте** (`"ids": {"1": "fertile", ...}`), импорт перенумеровывает по имени |
| Библиотеки | контент: `content/config/terrain/*.json` | именованные кирпичи: почвы, скалы склонов, шумы, наземный фолиаж, виды леса, наборы декораций, наборы декалей, типы воды |
| Категории | контент: `content/config/terrain/categories.json` | id → выбор из библиотек + параметры; наследование от базовой категории |
| Биомы слоёв | контент: `content/config/terrain/forest_biomes.json`, `water_biomes.json`, `decor_biomes.json` | id слоя → деревья, кустарники, подлесок, подстилка, мелкий декор / вода / наборы декора |
| Схема, загрузчик, валидатор, рантайм | движок | формат и проверка ссылок; генерация шейдерного кода и таблиц; размещение деталей по сиду; живая перезагрузка |
| Правки деталей | `<world>/source/details/` по чанкам, только суша | закреплённые и удалённые экземпляры декалей и декораций, множители густоты кистью |

Классы материала (`Grass, Dirt, Sand, Rock, Marsh, Snow`, `height_field.hpp:126`) остаются
физикой: *какая* поверхность здесь по склону, влажности и высоте. Категория решает, *какая
почва, какой камень, какая трава* стоят за каждым классом. id 0 — нынешнее поведение байт в
байт, поэтому обычные миры и отпечатки (`4242`: `b2f7ddb91db7a2b2`) не меняются.

## Категория (черновик формата)

```jsonc
// content/config/terrain/categories.json
{ "categories": [
  { "name": "wastes", "id": 6, "inherit": "default",

    "soils": {                                   // класс материала -> почва из библиотеки
      "grass": "grey_dust", "dirt": "grey_dust_rubble", "sand": "grey_dust", "marsh": "grey_sludge"
    },
    "slopes": {                                  // камень на склонах
      "rock": "grey_crumbling_cliff",            // из библиотеки rocks: слой, страты, осыпь
      "scree": "grey_rubble", "steep_from": 0.55
    },
    "ground_foliage": "none",                    // трава/мох/кочки из библиотеки foliage или "none"
    "decals": [["dust_streaks", 1.0], ["grey_stain", 0.6]],
    "defaults": {                                // биомы слоёв, где их слой = 0
      "forest": "charred_dead", "water": "rotten_green", "decor": "wastes_debris"
    },
    "look": { "tint": [0.92, 0.92, 0.95], "saturation": 0.35 },
    "controls": { "moisture": 0.06, "forest": 0.0, "erosion": 0.75 }   // значения по умолчанию для каналов
  }
]}
```

- `inherit` — категория берёт всё у родителя и переопределяет нужное (`swamp_forest` от
  `swamp`, `old_oak` от `fertile`). Не названный класс почвы — родительский.
- `controls` — что получают control-каналы, если карта их не задаёт. `assemble_controls.py`
  берёт эти значения из категорий, а не из своей таблицы `BASE_VALUES`. Один источник правды.
- Валидатор (`Content validator`): ссылки на библиотеки существуют, слои есть в каталоге
  текстур, id уникальны, доли в сумме 1, нет циклов наследования.

## Библиотеки

Кирпичи именованы и переиспользуются разными категориями.

```jsonc
// content/config/terrain/soils.json — почва: слои и шум, которым они мешаются
{ "soils": [
  { "name": "grey_dust", "layers": [["ph_moon_dusted_04", 0.8], ["ph_rubble", 0.2]],
    "noise": { "kind": "fbm", "metres": 14, "contrast": 0.6, "warp": 0.3 },
    "tint": [0.95, 0.95, 0.97], "metres_per_turn": 0.56 },
  { "name": "peat", "layers": [["ph_mud_forest", 0.7], ["ph_brown_mud_leaves_01", 0.3]],
    "noise": { "kind": "cellular", "metres": 6, "contrast": 0.8 } }
]}

// rocks.json — камень склонов: слой скалы, страты, осыпь у подножия
{ "rocks": [
  { "name": "grey_crumbling_cliff", "layer": "ph_rock_face_03", "strata": { "metres": 3.5, "tilt": 0.1 },
    "scree": "grey_rubble", "tint": [0.9, 0.9, 0.92] }
]}

// noises.json — виды шумов (общие для почв, декалей, фолиажа): fbm, cellular, streaks, ridged
// foliage.json — наземный покров: карточки травы, мох, кочки; высота, сухость, цвет
// plants.json — отдельные растения: деревья и кустарники (модель/импостер, высоты, цвет по сезону)
// props.json — отдельные предметы декора: бревно, пень, ветка, шишка, гриб, камень, кость
// decals.json — наборы декалей (ниже)
```

## Control-слои и их биомы

Каждый слой — свой categorical-растр 256 м (только суша), своя легенда, своя библиотека
биомов. id 0 — взять биом из `defaults` категории земли.

```jsonc
// content/config/terrain/forest_biomes.json — биом леса
{ "forest_biomes": [
  { "name": "beech_mixed",
    "trees":  [["beech", 0.55], ["hornbeam", 0.2], ["oak", 0.15], ["birch", 0.1]],
    "shrubs": [["hazel", 0.6], ["elder", 0.4]], "shrub_density": 0.35,
    "undergrowth": "fern_and_grass",              // наземный покров под пологом (foliage.json)
    "floor": { "soil": "leaf_litter", "noise": "fbm_8m" },   // подстилка: почва из soils.json
    "props": [["fallen_log", 6], ["stump", 10], ["branches", 80], ["mushrooms", 25]],   // на гектар
    "fertility": 0.8,                             // сколько леса даёт земля при forest_bias 0.5
    "density": { "by": "forest_bias", "curve": [[0, 0], [0.5, 0.6], [1, 0.95]] },
    "clearings": { "noise": "cellular_120m", "share": 0.15 },
    "edge": { "shrubs": 1.8, "metres": 25 }       // опушка: гуще кусты
  },
  { "name": "swamp_thin", "trees": [["swamp_pine_thin", 0.6], ["dead_birch", 0.4]],
    "undergrowth": "sedge_tussocks", "floor": { "soil": "peat" },
    "props": [["snag", 30], ["half_sunk_log", 12]], "fertility": 0.7 },
  { "name": "charred_dead", "trees": [["charred_trunk", 1.0]], "undergrowth": "none",
    "floor": { "soil": "grey_dust" }, "props": [["charred_stump", 8]], "fertility": 0.05 }
]}

// water_biomes.json — тип воды: цвет, мутность, плёнка/ряска, пена, свечение, частицы над водой
{ "water_biomes": [
  { "name": "clear", "colour": [0.10, 0.22, 0.26], "turbidity": 0.2 },
  { "name": "bog", "colour": [0.16, 0.12, 0.06], "turbidity": 0.8, "scum": 0.3 },
  { "name": "rotten_green", "colour": [0.18, 0.26, 0.06], "turbidity": 0.9, "scum": 0.7, "foam": 0.0 },
  { "name": "power_slime", "colour": [0.30, 0.85, 0.55], "turbidity": 0.95, "emissive": 0.6 },
  { "name": "tropical", "colour": [0.05, 0.40, 0.42], "turbidity": 0.1 }
]}
```

```jsonc
// decor_biomes.json — наборы декора вне леса: развалины, кости, обломки, мусор лагеря
{ "decor_biomes": [
  { "name": "wastes_debris", "props": [["bone_pile", 2], ["grey_boulder", 6], ["broken_cart", 0.2]],
    "decals": [["grey_stain", 1.0]] }
]}
```

Вода категории (или слоя `water`) применяется к озёрам, лужам и ручьям внутри неё. У большой реки, текущей
через несколько категорий, тип воды плавно меняется по течению: смешивание по доле
категории на 256 м, как у земли.

## Декали — привязаны к id

Набор декалей включает категория; без категории декали нет. Control-каналы могут только
подкрутить густоту включённого набора (`"by": "forest_bias"`), но не включить чужой.

Два семейства в одном формате:

1. **Шейдерные** (`kind: "speckle" | "stain" | "streak"`) — ничего не хранится. Пиксель
   хеширует свою клетку (как `landscapeCloudJitter`: малые числа, привязка к земле), решает,
   есть ли в ней пятно, и рисует форму процедурно или из атласа альф (`assets/PHX_Alphas_LITE`,
   `VOL1_TerrainAlphas` уже лежат). Бесплатно по памяти и видно с любой высоты как шум цвета.
2. **Экземплярные** (`kind: "instance"`) — проекция или модель: пятно кратера, выход руды.
   Позиции выводятся из (сид мира, чанк, набор) детерминированно при генерации страницы.

```jsonc
// content/config/terrain/decals.json
{ "decals": [
  { "name": "grodomantite", "kind": "speckle",
    "cell_m": 1.5, "density": 0.18, "size_m": [0.08, 0.35], "cluster": { "cell_m": 24, "share": 0.4 },
    "colour": [0.78, 0.06, 0.05], "emissive": 0.15, "metal": 0.8, "rough": 0.35,
    "slope": [0.0, 0.9], "under_foliage": 0.3, "fade_m": [0, 600] },
  { "name": "black_wind_stain", "kind": "stain",
    "cell_m": 18, "density": 0.6, "size_m": [6, 22], "colour": [0.05, 0.04, 0.06],
    "edge_noise": 0.6, "fade_m": [0, 12000] },
  { "name": "dust_streaks", "kind": "streak", "cell_m": 8, "density": 0.4, "along": "wind",
    "colour": [0.62, 0.62, 0.64] }
]}
```

Декорации (брёвна, пни, ветки, камни, кости) устроены так же, как экземплярные декали: набор
в библиотеке, включение и густота в категории, позиции от сида, правки отдельно. Валежник
леса — часть вида леса (`forests.json`), а не набора декораций: он идёт за деревьями.

**Хранение правок** (`<world>/source/details/<cx>_<cy>.json`, только чанки суши с правками):

- `pinned` — экземпляр, поставленный рукой. Не исчезает при перекраске id.
- `removed` — хеши выведенных экземпляров, которых не должно быть.
- `density` — плитка множителей кистью.

Перекрасили id — выведенные детали перестраиваются, закреплённые остаются. Экспорт и импорт
мира несут эти файлы как векторный слой.

## Сборка шейдеров из конфига

Конфиг не интерпретируется шейдером на каждом пикселе. Из него **генерируется код**:

- **Что генерируется.** `assets/shaders/terrain_biomes.gen.hlsli` (в `.gitignore`):
  - константы слоёв текстур;
  - по функции на категорию и биом, где вызываются только используемые виды шумов и декалей;
  - `switch` по id;
  - список включённых семейств декалей.

  Неиспользуемые шумы и декали в шейдер не попадают.
- **Когда.** При запуске — если конфиг новее сгенерированного файла. В редакторе — по
  сохранению конфига. И из CLI (`worldtool biomes --emit`) для проверок без клиента.
- **Почему это дёшево.** Кэш SPIR-V уже ключуется по содержимому всех файлов папки шейдеров
  (`Device::shaderKey`, `device.cpp:200-220`). Новый `.gen.hlsli` меняет ключ — шейдеры
  перекомпилируются один раз. Тот же конфиг — тот же файл байт в байт, без перекомпиляции.
  Генератор пишет детерминированно: сортировка по id, без времени и путей.
- **Что требует перекомпиляции, а что нет.**
  - Структура (какие шумы, сколько слоёв, какие семейства декалей у категории) — код,
    перекомпиляция.
  - Числа (тон, густота, размеры, цвета, доли) — таблицы-текстуры, обновляются на лету без
    перекомпиляции.

  Живая правка ползунком в инспекторе не дёргает компилятор.
- **Ошибки.** Генератор сначала прогоняет валидатор. Шейдер, не собравшийся из
  сгенерированного кода, откатывается на прошлый рабочий `.gen.hlsli`, а ошибка видна в
  редакторе.

## Как это попадает на GPU

- **id-поле.** Плоскость 3 поля климата (`ClimateField::kPlanes`, `climate_field.hpp:80`;
  все 12 каналов заняты): `idA, idB, blend, spare`. На границе категорий — два id и доля.
  Доля считается от расстояния до границы на 256 м и рвётся шумом в шейдере. Категории не
  фильтруются билинейно, поэтому именно пара id с долей, а не одно id.
- **Таблицы категорий** — маленькие `Texture2D`, строка на категорию:
  - почвы по 6 классам: слои, доли, шум;
  - скала склонов и порог крутизны;
  - тон и насыщенность;
  - слоты шейдерных декалей;
  - тип воды.

  Обновляются при правке конфига без пересборки мира (живая перезагрузка в редакторе).
- **Слои текстур.** `GROUND_LAYERS` 16 → 22 (`terrain_material.hlsli:176`, `kLayerMetres`,
  список `world_renderer.cpp:146-152`). Это примерно +180 МБ, на M3 Pro не страшно. Если
  слоёв станет много — грузить в массив только слои категорий, которые есть в мире.
- **Шейдер террейна.** `groundVariants` (`terrain.hlsl:265-315`) получает категорию: почва
  класса, её шум и скала склонов берутся из таблицы. Без категории (id 0) — как сейчас.
- **Вода.** Шейдер воды (`water_pages.hlsl`, `water_scene.hlsli`) читает тип воды из таблицы
  по id под водой.
- **CPU.** Фолиаж, лес и декорации читают категорию и биомы слоёв (`forest`, `decor`) на
  странице вместе с control-каналами: какие деревья, кустарники, предметы и с какой густотой.

## Настройка под текущий мир (континент и острова, `doc/references/heights`)

id — из `ground_legend.json`, карты собирает `assemble_controls.py`. Зоны, которые говорят
только о лесе (хвойные, старый дуб, жуткий лес Эльнора; тонкий болотный лес Топей;
саванновый лес Ксаириниса; обугленные стволы Пустошей), в фазе 1 переезжают из категорий
земли в слой `forest` — категория земли под ними остаётся своей (`fertile`, `swamp`, …).
Колонка «Лес» ниже — это биомы леса. Наследование категорий:
`swamp_forest` ← `swamp`, `old_oak`/`conifer`/`eerie` ← `fertile`, `charred` ← `wastes`,
`savanna_wood` ← `savanna`, `jagged` ← `rock`, `scarlet` ← `tropical_soil`, `crater` ← `tropical_soil`.

| Регион | Категории | Почвы | Склоны | Наземный покров | Лес | Декорации | Декали | Вода |
|---|---|---|---|---|---|---|---|---|
| **Кагар** | `fertile` (старые леса кольца), `sparse` (сыроватое редколесье), `rough` (зернистая почва, сланец, известняк), `swamp` (пояс вокруг Верховья), `rock` (массив) | rough: `rocks_ground_05` + `sandy_gravel_02`, холоднее; swamp: `brown_mud_02` + мшистая | rough и rock: серый сланец со стратами, осыпь | трава; на swamp — кочки | fertile: старый смешанный, густо; sparse: редкий | валежник, мшистые камни | сланцевый щебень (speckle) на rough | swamp: `bog`; озеро — `clear` |
| **Топи** | `swamp` | grass → мшистая грязь, dirt/marsh → торф | мало склонов: торфяные обрывы | кочки, осока | `swamp_thin` (длинные тонкие, густо) | коряги, полузатопленные брёвна | ряска на мелководье (stain у воды) | `bog` |
| **Атрод** | `fertile` (долины и равнины), `rough`, `rock`, `jagged` (южная гряда) | fertile: `leafy_grass` + `withered_grass` | jagged: острая серая скала, мало осыпи; rock: плавнее | трава и кустарник | мало деревьев, много кустарника | камни, редкие пни | — | `clear`; болотце внизу — `bog` |

## Фазы

0. **Легенды в источнике.** `ground`, `forest`, `water`, `decor` с `"ids"` в манифесте; импорт по региону
   перенумеровывает по имени. Неизвестное имя — ошибка импорта с подсказкой.
   Проверка: `worldtool import`/`info`, тест транспорта на перенумерацию.
1. **Схема и реестр.** Библиотеки, категории, биомы слоёв (`forest`, `water`, `decor`),
   загрузчик в движке, наследование, валидатор; `assemble_controls.py` читает `controls`
   категорий и пишет слои `forest`/`water`/`decor` там, где карта их задаёт (зоны Эльнора —
   биомы леса, а не категории земли). Проверка: валидатор, отпечаток 4242 не меняется.
2. **Генератор шейдерного кода** (`terrain_biomes.gen.hlsli` + таблицы), запуск по
   изменению конфига, откат на прошлый рабочий. Проверка: тот же конфиг — тот же файл, без
   перекомпиляции; правка числа — без перекомпиляции; правка структуры — одна.
3. **id на местности.** `ImportedGround::ground`. У сгенерированных миров категория
   выводится правилом из климата (Desert → `desert`, болото по стоку → `swamp`, …), чтобы
   система была общей, а не только для импорта. Проверка: проба `--import ... 8x17`
   печатает доли категорий.
4. **Земля на GPU.** Плоскость 3 климата, таблицы категорий, слои 16–21, почвы, шумы и
   склоны в `groundVariants`. Проверка: тур по Пустошам, Топям и Ксаиринису; без категорий —
   те же кадры.
5. **Вода по категории.** Тип воды в шейдере воды. Проверка: зелёная гнилая вода в
   Пустошах, бурая в Топях.
6. **Шейдерные декали** (speckle/stain/streak). Проверка: `grodomantite` на П и А,
   `black_wind_stain` на Е; не мерцают при движении (привязка к земле).
7. **Лес, наземный фолиаж и декор по биомам слоёв.** Деревья и кустарники, подлесок,
   подстилка, мелкий декор и их густота; наземный покров категории или ничего; биомы
   декора; экземплярные декали.
8. **Хранение правок деталей** (`source/details`: pinned/removed/density).
9. **Редактор.**
   - Кисть id по регионам (поверх импорта, тем же `transfer`).
   - Инспектор категории с живой перезагрузкой.
   - Кисть густоты деталей, закрепление и удаление экземпляра.

Правила как везде: `-j 2`, одна сборка за раз; короткие проверки, остальное — глазами в игре.
Атродиним (бирюзовый металл) заводится так же — декаль и, если нужно, категория, когда
появится на картах.
