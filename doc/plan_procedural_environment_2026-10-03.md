# План: процедурный энвайронмент и стиль 80-х — механизм в движке, конкретика в игре

Источники: `doc/procedural_environment_generation_spec.docx`,
`doc/fantasy_80s_art_asset_style_spec.docx`. Состояние на 2026-10-03.

**Порядок работ.** Сначала весь механизм и инструменты (части A–I), потом
конкретные зоны, рецепты и стиль (часть J). Конкретика ещё не утверждена. Пока
делаем только натуральные, реальные зоны. Фентезийные биомы (Amber Grove,
Flower Valley и т.д.) и фентезийные макроформы (шпили, кольцевые горы,
невозможные арки) механизм должен уметь, но контента для них не делаем.

## 0. Граница engine / game

Правило: **движок знает, *как* генерировать и рисовать; игра знает, *что*.**

| Что | Engine (`src/engine/environment`, `assets/shaders/*.hlsli` движка) | Game (`src/game/environment`, `content/config/environment`, `content/config/style`, `assets/shaders/game/`) |
|---|---|---|
| Поля | интерфейс выборки полей, производные (уклон, кривизна, конвергенция, TPI, экспозиция), реестр имён полей | адаптеры к `HeightField`, `ClimateField`, `ecology`, гидрографу, почве |
| Зоны | `EnvironmentZone`, мягкая принадлежность, решётка зон, сглаживание по причинам, кэш | **классификатор на C++** (`ZoneClassifier`): какие типы зон есть и как они выводятся из полей |
| Рецепты | схема JSON, парсер, валидатор, примитивы: рельеф, маски, разброс, композиция, меш-фичи; планировщик экземпляров | **рецепты в JSON** (`content/config/environment/recipes/*.json`) |
| Дренаж прошлого | построитель микросети стока, классы русел, сплайны, поля расстояний «дно/берег/бровка» | откуда берётся исторический сток (климат прошлого, множители) |
| Наземный покров и разброс | ярусы, многомасштабные пятна, кластеры, иерархия камней, веера осыпей | какие модели, плотности, цвета, правила по зонам (JSON) |
| Маски | 8 каналов влияния на страницу (2 RGBA-плоскости), растеризация, загрузка в GPU | значение каналов (имена в JSON) |
| Стиль материала | хук `styleSurface()` в шейдерах террейна, моделей, листвы и воды; таблица параметров стиля по регионам | тело хука `assets/shaders/game/style_surface.hlsli` + `content/config/style/palettes.json` |
| Грейдинг | проход грейдинга с регионами, смешивание профилей, 3D LUT, хук `stylePicture()` | тело хука `assets/shaders/game/style_picture.hlsli` + `content/config/style/grades.json` |
| Ассеты | схема метаданных (лицензия, автор, правки, теги размещения), валидатор, конвейер стилизации текстур (операции) | пресеты стилизации, теги размещения, палитры |
| Инструменты | оверлеи отладки, инспектор экземпляров, пробник CLI, горячая перезагрузка | — |

Направление зависимостей прежнее: `src/engine` не включает `game/`. Игра
подключается тремя путями:
1. регистрирует C++-реализации интерфейсов при запуске (классификатор зон,
   адаптер полей);
2. отдаёт JSON, который читает движок;
3. кладёт тела шейдерных хуков в `assets/shaders/game/`. Шейдер движка делает
   `#include "game/…"`: путь include один — каталог шейдера.

Существующий код генерации в game (`world_map_gen`, `HeightField`,
`ClimateField`, `scene_scatter`, `ecology`) переносится в движок **только там,
где его касается эта работа**. Здесь это:
- обобщённая часть `decor::scatter`: решётка кандидатов, пятна, кластеры;
- `GradePass`.

Остальное остаётся в game.

## A. Поля окружения (engine)

`engine/environment/fields.hpp`
- `FieldId` — индекс в реестре имён (`"slope"`, `"wetness"`, `"soil_depth"` …).
  Движок задаёт базовый набор имён, игра может добавить свои.
- `FieldSample` — плоский массив float по индексам реестра (до 32 полей) и
  маска того, какие поля заполнены.
- `FieldSource` — интерфейс `sample(x, y, FieldSample&)` и
  `sampleGrid(rect, step, span<FieldSample>)`. Пакетный вариант нужен для
  скорости: страница спрашивает сотни точек.
- Базовые поля, которые движок умеет вывести сам из `HeightAt`:
  - `slope`, `aspect`;
  - `curvature` (профильная и плановая);
  - `convergence`;
  - `tpi`: топографическая позиция на двух радиусах, 32 и 128 м;
  - `exposure` к ветру и солнцу по заданному вектору.
- Поля, которые отдаёт игра: `elevation`, `wetness`, `moisture`, `fertility`,
  `soil_depth`, `drainage`, `temperature`, `canopy`, `rockiness`,
  `disturbance`, `flow_accum`, `dist_water`, `age` и т.д.

## B. Зоны окружения (engine-механизм, game-классификатор)

`engine/environment/zones.hpp`
- `EnvironmentZone { type, density, wetness, exposure, age, disturbance,
  rockiness, canopy, soilDepth }` — как в спецификации. `type` — `ZoneTypeId`
  из реестра. Реестр наполняет игра: имя, цвет для отладки.
- `ZoneClassifier` (интерфейс) — `classify(const FieldSample&) ->
  ZoneWeights`: до 4 типов с весами, а также скаляры зоны. Принадлежность
  **мягкая**, поэтому переход — это смешивание весов, а не порог.
- `ZoneField`:
  - решётка 16 м поверх страницы 512 м с полем-ободком;
  - сглаживание весов ядром, вытянутым вдоль градиента причин (уклона, стока).
    Шум применяется только как разбивка амплитудой ≤ заданной, не как причина;
  - кэш по странице с ключом (поколение конфига, ревизия правок);
  - чистая функция координат: соседние страницы получают одинаковые числа.
- `dominant(x, y)`, `weights(x, y)`, `scalar(x, y, field)`.

Отношение к `ecology::Biome`: биом экологии остаётся грубым симуляционным
слоем (64 м). Зона — семантический слой для размещения. Классификатор игры
может читать биом экологии как одно из полей.

## C. Рецепты фич (engine-схема и примитивы, game-JSON)

`engine/environment/recipe.hpp`, `recipe_json.cpp`, `recipe_validate.cpp`

```
FeatureRecipe {
  name, scale: micro|local|macro, age: geological|ancient|recent|cataclysmic (по умолчанию),
  placement:   { zones[], fields{имя:[min,max]}, source: point|channel|ridge|cliff_foot|edge,
                 density_per_km2, min_spacing, rarity, cluster{...}, align: slope|flow|wind|ridge|none },
  terrain:     [ op... ],      // изменения высоты
  meshes:      [ rule... ],    // меш-фичи (свесы, полки, корневые плиты)
  materials:   [ mask... ],    // запись каналов масок
  scatter:     [ rule... ],    // поддерживающий декор
  composition: { anchor, secondaries, negative_space, elongation, reveal_corridor }
}
```

**Операции рельефа.** Все считаются в `core::Fixed`: они двигают H_sim, а по
H_sim ходят. Каждая операция — чистая функция `(экземпляр, точка) -> Δh` с
ограничивающим прямоугольником.
- `carve_profile` вдоль сплайна. Вложенный профиль на трёх масштабах:
  внешняя долина, внутреннее русло, текущая вода. Задаётся ширина и глубина
  каждого и асимметрия (подмываемый берег зависит от кривизны сплайна).
  Операция отдаёт поля расстояний `bed`, `bank`, `edge`.
- `step` — ступень или эскарп по сплайну через знаковое расстояние: высота,
  ширина склона, разрывы, амфитеатры.
- `raise` и `depress` — эллипс с профилем, опциональной «твёрдостью»
  (`harden`: пишет маску камня) и шумом края.
- `terrace` — ступени по уровням в пределах области.
- `smooth_to` — притягивает к плоскости или ко дну, для площадок и
  подножий.

Возраст смягчает края (радиус размытия, сглаживание бровки) и решает,
приспособились ли сток и экология. «Recent» пишет маски шрамов и сухостоя.
«Cataclysmic» сохраняет обрывы и висячие русла.

**Маски.** Запись в каналы `wetness`, `suppress`, `boost`, `rock`, `talus`,
`litter`, `moss` и т.д. По форме: по полю расстояния операции, по радиусу, по
вееру ниже по склону.

**Разброс.** Ссылки на примитивы раздела E:
- `cluster` вокруг якоря;
- `fan` — осыпь ниже источника;
- `along_channel` — речные камни с уменьшением размера вниз по течению;
- `ring` и `edge`;
- `line` вдоль вектора.

**Композиция.**
- Один якорь и N вторичных элементов.
- Пустое пространство: радиус, внутри которого разброс других рецептов
  подавляется.
- Вытянутость и ориентация по вектору окружения.
- Коридор подхода: полоса без высоких объектов.

**Планировщик экземпляров** (`engine/environment/planner.hpp`):
- Ячейки планирования по масштабу: micro 128 м, local 512 м, macro 8 км.
  Кандидаты — дрожащая решётка с отбраковкой Пуассона по `min_spacing`.
  Проверка `placement` идёт по `ZoneField` и полям.
- Источники `channel`, `ridge` и `cliff_foot` берут кандидатов из сети стока
  (раздел D) и поиска гребней и подножий.
- Выход: `FeatureInstance { recipe, seed, anchor, yaw, scale, spline[],
  age, bounds }`. Чистая функция `(seed, ячейка, конфиг)`. Соседи
  спрашиваются через ободок размером в максимальный радиус фичи, чтобы фича
  через границу страницы была одной фичей.
- Кэш по ячейке, инвалидация по поколению конфига и ревизии правок.

**Слой высот фич** (`FeatureHeightLayer`):
- Разреженный индекс экземпляров по блокам 512 м.
- `at(x, y) -> Fixed`. Пустой блок обходится одной веткой, как у
  `EditLayer::empty()`.
- `HeightField` (game) добавляет его в `sampleHeight` между деталью и
  правками. Навмеш, проходимость и вода видят овраг.
- Порядок фиксирован: страна → деталь → фичи → русла гидрографа → правки.
  Реки из гидрографа остаются единственным авторитетом по воде: операция
  рельефа не углубляет живое русло. Маска `river_share` гасит её Δh.

## D. Исторический дренаж (engine)

`engine/environment/drainage.hpp`
- Микросеть стока на локальной решётке (8–16 м) по высоте, кривизне,
  конвергенции, эродируемости и «историческому потоку». Исторический поток —
  множитель, его задаёт игра (климат прошлого).
- Классы русел: `PermanentRiver`, `SeasonalStream`, `EphemeralChannel`,
  `AbandonedChannel`, `Paleochannel`. Класс зависит от отношения текущего
  потока к историческому.
- Выход: сплайны русел с шириной трёх масштабов. Это источник для рецептов
  с `source: channel`, например «сухой овраг».
- Старицы и брошенные меандры отдаются как кандидаты для рецептов «сырая
  лощина» и «старица».
- Вода в овраге:
  - текущая ширина 0 — сухое дно, только маска `wetness`;
  - ширина больше 0 — мелкая стоячая или ручейная вода, тем же путём, каким
    сейчас делаются болотные лужи (`bogPoolDepth`): пекарь страницы пишет
    воду, а гидрограф не трогается;
  - настоящие притоки в гидрографе — отдельный шаг позже (часть K).

## E. Покров и разброс (engine-примитивы, game-правила)

`engine/environment/scatter.hpp`. Сюда переезжает обобщённая часть
`world::decor::scatter`: решётка кандидатов, детерминированные id, дрожание,
бюджеты.

Ярусы:
1. **Микродеталь материала** — в шейдере, по маскам `litter`, `gravel`,
   `needles`.
2. **Покров** (трава, мох, тростник, вереск). GPU, `foliage_pages.hlsl`.
   Плотность — функция зон и масок через хук `envCover()`. Многомасштабные
   пятна: 3–10 м внутри 20–100 м.
3. **Вторичный разброс** (цветы, папоротник, кусты, ветки, мелкие камни).
   CPU. Правило зоны с кластерной пятнистостью.
4. **Композиции фич** (брёвна, валуны, скальные группы, сухостой).
   Разброс рецептов.

Примитивы:
- `patchField(seed, scales[])` — многомасштабные вытянутые пятна вдоль
  вектора, не круглые острова;
- `cluster`, `fan`, `along_channel`, `ring`, `edge`, `line`;
- `RockHierarchy`: коренная порода → скала → валун → группа → булыжник →
  галька → осыпь. Размер, угловатость и окатанность зависят от источника
  (обрыв или русло) и расстояния от него;
- `negative space`: подавление по маске `suppress` и по радиусам композиций.

Правила по зонам (JSON игры): для каждого типа зоны и яруса — набор моделей,
плотность, кривая по каналам масок и по полям, масштаб пятен, цвет.

Существующие `forest_biomes`, `decor_biomes` и категории остаются. Зона
*модулирует* их плотность и выбор, а не заменяет. Категория отвечает «какой
это лес», зона — «какая это часть леса».

## F. Меш-фичи (engine)

`engine/environment/feature_mesh.hpp`
- Правило меша в рецепте: модель или набор из каталога либо процедурная
  форма, привязка к якорю или сплайну, посадка с утоплением и выравниванием
  по нормали или вертикали.
- Процедурные формы для натурального контента:
  - полка, карниз или свес обрыва — лофт по сплайну бровки;
  - подмытый берег;
  - корневая плита упавшего дерева.

  Реализация: SDF → сетка (surface nets) → существующий кластерный конвейер
  (`engine/geometry/cluster_asset`). Кэш по (рецепт, seed).
- Последовательность смешивания из спецификации:
  1. деформация рельефа;
  2. меш;
  3. переопределение материала;
  4. подавление или усиление растительности;
  5. переход осыпь/обломки;
  6. микродеталь.

  Шов «камень воткнут в землю» закрывают маски `talus` и `contact` вокруг
  основания.
- Фентезийные формы (шпили, арки, «грибы») — тот же механизм, контент позже.

## G. Маски на GPU (engine)

- `BakedPage` получает `envMasks`: 8 каналов u8 на сетке материалов.
- `height_page_stream` кладёт их в `fields` как плоскости 4 и 5.
- Шейдерная функция движка `envMask(uv, channel)`.
- Растеризация масок на воркере страницы:
  1. зоны (веса до 4 типов → id и вес двух главных в одном канале-паре);
  2. затем маски экземпляров.
- Оверлей отладки (`editor_overlay.hlsli`): зона, канал маски, экземпляры.

## H. Стиль (engine-хуки, game-тела)

**Материал.** Хук `styleSurface(inout StyleSurface s)`:
- вход: базовый цвет, шероховатость, сила нормали, AO, класс материала
  (rock, soil, wood, leaves, metal, water), мировая позиция, дистанция,
  веса зон, id региона стиля;
- вызывается в `terrain.hlsl`, `scene_models.hlsl`, `foliage.hlsl`,
  `water.hlsl` до освещения;
- тело игры — поток из спецификации: палитра → оттенок тени → оттенок
  блика → макровариация → форма шероховатости → печатный/зерновой отклик.

Параметры регионов:
- движок держит таблицу «регион стиля → N float4». Смысл чисел задаёт игра;
- регион стиля выбирается по категории и зоне (JSON игры);
- оттенки тени и блика, которые зависят от освещения, — второй хук
  `styleLit(inout StyleLit l)` после освещения.

**Картинка.** `GradePass` переезжает в движок
(`engine/render/passes/grade_pass`):
- профили грейдинга смешиваются по региону камеры со временем перехода;
- профиль — параметры и опциональный 3D LUT (`.cube` или запечённый из
  параметров);
- хук `stylePicture(inout StylePicture p)` с телом в игре: тёплые
  света/холодные тени, filmic, зерно, ореол, мягкая квантизация «печати»,
  виньетка;
- атмосферная перспектива: хук `styleHaze()` с цветом дымки по региону.

**Листва.** Палитры по биому и сезону в JSON игры. Далёкие кроны
сливаются в массы: импостору задаётся упрощение палитры, механизм — в
движке.

## I. Ассеты и инструменты

- **Метаданные ассета** (engine-схема, `engine/environment/asset_meta`):
  - источник, автор, лицензия, правки, ограничения распространения;
  - категория, совместимые зоны, теги размещения.

  Валидатор подключается в `tools/content_validator.cpp` и отклоняет ассет
  без лицензии.
- **Конвейер стилизации текстур** (`tools/stylize_textures.py`). Операции
  движка, пресеты игры:
  - снижение микроконтраста;
  - ослабление нормали с сохранением крупных форм;
  - перекраска в палитру;
  - лёгкая постеризация;
  - упрощение шероховатости;
  - региональные варианты.
- **Инструменты:**
  - горячая перезагрузка `environment/*.json` и `style/*.json`, как у
    биомов (`setActive`);
  - вкладка редактора «Environment»: список экземпляров рядом с курсором,
    инспектор рецепта, переключатели оверлеев, кнопка «пересчитать
    страницу»;
  - `tools/environment_probe.cpp`: гистограмма зон, число экземпляров по
    рецептам, время по стадиям на заданной области; режим детерминизма
    (два прогона, побитовое сравнение);
  - тесты: детерминизм, бесшовность на границе страниц, пустой слой ничего
    не стоит, валидатор отклоняет плохие рецепты, иерархия камней,
    негативное пространство.

**Пайплайн рантайма страницы** — порядок из спецификации:
1. поля;
2. зоны;
3. экземпляры (макро, потом локальные);
4. Δh в H_sim;
5. меш-фичи;
6. вода в оврагах;
7. маски;
8. покров;
9. вторичный разброс;
10. декор фич;
11. LOD и кэш.

Всё детерминировано от seed. Хранятся только ручные правки — существующие
`DetailEdits` плюс правки экземпляров: удалить или сдвинуть экземпляр.

## J. Конкретика игры (на утверждение, после механизма)

Предлагаемые натуральные зоны (классификатор C++):
- лес: густой старый, редкий, опушка, поляна, ветровал, сырая лощина,
  приручейная полоса, подножие обрыва, каменистый склон;
- открытые земли: луг, кустарник, вереск/пустошь, степь, сухая промоина;
- вода: пойма, заболоченный лес, болото/топь, прибрежная полоса, песчаный
  берег и дюны;
- горы: осыпь, скальный выход, альпийский луг, тундра.

Предлагаемые натуральные рецепты (JSON):
- сухой овраг (палеорусло);
- старица и сырая лощина;
- обрыв/эскарп с осыпью;
- скальный выход;
- поле валунов (эрратики);
- упавшее старое дерево;
- ветровальная группа;
- речной перекат с камнями;
- подмытый берег с корнями.

Стиль:
- базовые палитры для натуральных регионов (умеренный лес, хвойный лес,
  степь, горы, болото, побережье);
- профили грейдинга к ним;
- текущий «тёплый сказочный» грейд (D163) становится профилем по умолчанию.
