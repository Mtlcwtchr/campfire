# План: мир 800 × 2000 км — море без данных, реки локально, континенты без мгновенной сборки

Референс — мир **6 × 15 регионов = 786 × 1966 км** (`world::saves::kReferenceRegionsX/Y`).
Цель по таблице `doc/hybrid_authored_procedural_living_world_spec.docx` (§4, §18): глобально
держится только грубое (256–512 м, единицы байт на ячейку), всё тонкое — кусками по окну
вокруг камеры и с диском как кэшем. **Итог: пустой референс < 300 МБ, референс с сушей < 2 ГБ,
правка в одном регионе не пересобирает остальные.**

Что уже сделано и на чём стоит план: D151–D153 в `doc/DECISIONS.md` — сборка мира из
генераций (`src/game/generation/world_compose.*`), разреженные поля клеток
(`src/game/generation/cell_field.hpp`), H64 окном без пребейка
(`TerrainView::window`, `GpuTerrain::window`), климат 256/512 м.

## Как мерить (до и после каждого шага)

```bash
cmake --build cmake-build-relwithdebinfo --target world_load_probe -j 2
./cmake-build-relwithdebinfo/world_load_probe --empty 6x15      # пустой референс: время и память по шагам
./cmake-build-relwithdebinfo/world_load_probe --reference       # референс + участок 2x1 своим прогоном
./cmake-build-relwithdebinfo/world_load_probe --grow            # стабильность: старое не меняется ни на бит
./cmake-build-relwithdebinfo/world_load_probe --no-prebake      # отпечаток фундамента мира 4242: b2f7ddb91db7a2b2 (сид 7: 12b71a77ce8201b)
```

Правила: `-j 2`, одна сборка за раз (машина с малой памятью). Отпечатки обычных миров
не должны меняться, пока шаг сам не меняет генерацию. Быстрые наборы тестов:
`asr_world_system_tests`, `asr_terrain_tests`, `asr_ui_tests`, `asr_tests world_`.
Тур клиента — с кэшем вне проекта, чтобы не забить диск:
`ASR_TERRAIN_CACHE_DIR=/tmp/tourcache campfire_client --client --client-tour /tmp/tour --headless 1280x720`.

Сначала проверить: 4 теста в `asr_height_page_gpu_tests` падают уже сейчас
(публикация атласа, вода на сухой грубой странице, материалы по зуму, эрозия).
Кэш шейдеров и текстур исключены (`ASR_SHADER_NO_CACHE=1`, `ASR_TEXTURE_NO_CACHE=1` —
те же падения). Подозрение — оверлей редактора в `terrain_pages.hlsl`/`water_pages.hlsl`
(`editor_overlay.hlsli`). Починить до остального, чтобы было по чему ловить регрессии.

**Статус (D154):** GPU-тесты 55/55 — оверлей ни при чём, тесты отставали от
закоммиченных решений. Из п. 1 сделано: климат без копий поля, климат кусками
с общими кусками, маска суши плитками, сток `MacroWorld` разреженный и общий,
отпечатки графа/страниц по кускам (`core::LaneHash`), канонический отпечаток
фундамента запоминается. `--empty 6x15`: пик 845 → 338 МБ, снапшот ~0.2 с.
Осталось для < 300 МБ: `cells` в `CellField` (67 МБ) и фундамент (163 МБ, п. 2);
климатические текстуры для карты (`ClimateField::plane`) пока плотные.

## 1. Море ничего не стоит

Сейчас пустой референс — ~1 ГБ пика (замер `--empty 6x15`). Из этого:

| Что | Сейчас | Сделать |
|---|---|---|
| Фундамент H64 (`TerrainFoundation`): 5 стадий `heightDm` + `receiver` + `accumulation`, плотно на весь мир | ~170 МБ, всё −600 дм | кусками, только суша и шельф (п. 2) |
| `WorldMapData::cells` — плотный `std::vector<WorldCell>` | ~71 МБ | `CellField<WorldCell>` с заливкой «море», см. ниже |
| `ClimateField` | ~73 МБ | хранить только куски с сушей; море — аналитически из широты (`Latitude`) |
| копии `HeightField` на каждый поток в `ClimateField::raise` | +280 МБ временно | делить одно const-поле (у `surfaceClimateAt` нет изменяемых кэшей) или завести лёгкий «климатический» вид поля без кэшей высот |
| `LandMask64` (`terrain::makeLandMask64`) | ~47 МБ нулей | разреженно: по региону флаг «вся вода / вся суша / смешано», биты только для смешанных |
| временные массивы сборщика (`pointRun`, метки массивов суши) | ~50 МБ | по регионам, не по всему миру |
| таблицы кусков `CellField` | ~20 МБ | терпимо; можно одну таблицу «регион → есть ли данные» на все поля |

Детали:
- **`cells` разреженно.** `WorldMapData::at()`, `cells[i]` и циклы по `cells` — по всему коду
  (`hydrology_builder.cpp`, `height_field.cpp`, `base_tile_baker.cpp`, `world_builder.cpp`…).
  `CellField<WorldCell>` уже умеет индекс, `size()` и чтение; циклы «по всем клеткам»
  переписать на обход кусков, иначе их стоимость остаётся O(мир).
- **Отпечатки** (`fingerprintOf` в `hydrology_builder.cpp`, `fingerprint` в
  `baked_page_cache.cpp`) сейчас обходят все клетки мира. Для `CellField` хешировать по
  кускам: отсутствующий кусок = константа. Это же даст локальные отпечатки для п. 3 и 5.
- **Граф стока** уже выходит сразу, если суши нет (`buildHydrologyGraph`), но его
  per-cell массивы (`downstream`, `bodyOfCell`, `inflow`, `startNode`/`endNode`,
  `resolveHydrology`) заводятся на весь мир при любой суше — после п. 3 они станут
  по массивам суши.
- Критерий: `--empty 6x15` < 300 МБ пика, < 0.5 с на снапшот.

## 2. Фундамент H64 на 64 м для большого мира

Сейчас `foundationStepFor` (`terrain_foundation.hpp`) удваивает шаг, пока решётка на весь
мир не влезет в 16 млн точек: у референса шаг **512 м**, и `generateLayoutWorld` пересэмплирует
в него прогоны, сделанные на 64 м (`runSample` в `world_compose.cpp`). Рельеф референса в
8 раз грубее мира в один регион. Честные 64 м плотно — 377 млн точек, ~10 ГБ.

Сделать:
- `TerrainFoundation` — **куски** (например, 64 × 64 точки = 4 км), заводятся только там,
  где не открытое дно; вне кусков `sample()` отдаёт дно.
- В рантайме держать **одну итоговую стадию** (Slopes), `int16` (−600…+45000 дм влезает со
  смещением), сток — направлением (`int8`) и `uint16`-логарифмом накопления. Стадии 0–3 нужны
  только генератору и отладочному виду стадий — хранить их на диске или не хранить.
- Сборщик **копирует куски прогонов**, не пересэмплирует; шаг всегда 64 м.
- Куски — продукт с диска (`.cache/terrain/…`, ключ — прогон + его отпечаток), в RAM —
  окно вокруг камеры плюс то, что просят генерация и граф стока.
- Проверить потребителей: `HeightField` (`piecesAt`, `sample`), `BaseTileBaker`,
  `refineLakesOnCarvedGround`, `naturalBasin`, `GraphCarver`, `applyTo`, сохранение
  `saveTerrainFoundation`/`loadTerrainFoundation`.
- Критерий: референс с сушей 30% — фундамент < 600 МБ в RAM при открытом мире; мир в один
  регион — отпечаток тот же, что сейчас.

## 3. Граф рек пересобирается только там, где изменилось

Сейчас `buildHydrologyGraph` строит граф всего мира после любой правки: у референса с двумя
регионами суши это 7 с в фоне (профиль: `fitCoursesToCarvedGround` и
`refineLakesOnCarvedGround` через `GraphCarver`). Реки не пересекают море, значит граф
**распадается по массивам суши**.

Сделать:
1. **Массивы суши** (связные компоненты по `cells.sea`, 4-связность — так, как их уже ищет
   `generateLayoutWorld` для догена рек) с устойчивым идентификатором и **отпечатком по своим
   клеткам и своим кускам фундамента** (п. 1: хеш по кускам).
2. **Граф массива** — отдельный кусок: узлы, отрезки, озёра, страницы индекса. Строится
   тем же кодом, что сейчас, но по маске массива (per-cell массивы — на прямоугольник массива,
   не на мир).
3. **Кэш** графов массивов в памяти и на диске (`hydrology_cache.*` уже умеет файл графа;
   ключ — отпечаток массива + `kHydrologyGraphVersion`).
4. **Склейка**: общий `HydrologyGraph` — конкатенация кусков с переназначением ID (ID плотные,
   `n+1`, см. `hydrology_graph.hpp`), океан — один общий. Порядок детерминированный (по
   наименьшей клетке массива), иначе ID «плавают» между сборками.
5. После сборки мира: массивы, чей отпечаток не изменился, берут граф из кэша; строятся только
   новые/изменённые. Остров рядом с изменённым материком не трогается (по договорённости: нас
   интересуют только соседние регионы с общей сушей).
6. Инвалидация производного: страницы и меши, которые читали граф, устаревают только в
   прямоугольнике изменённых массивов (сейчас отпечаток страниц в `baked_page_cache.cpp`
   включает `graph.sourceFingerprint` и `spatialPages.size()` — меняется при любой правке и
   инвалидирует **весь** кэш страниц; заменить на версию графа массива, в который попадает
   страница).
7. Отдельно — вскопанная земля (D149: «вода не знает о копке»): мазок, углубивший русло,
   пересобирает граф своего массива в пределах бассейна вниз по течению.
- Критерий: правка слоя в одном регионе референса — граф пересобран < 1 с, у остальных
  массивов байт в байт тот же.

## 4. Рисование континентов без мгновенной сборки

Сейчас мазок по слою Continents в редакторе формы мира (`client/world_editor.cpp`,
`endStroke` → `wanted_` при `autoBuild_`; клиент включает `autoBuild(true)`) запускает полную
сборку мира: генерация прогонов, фундамент, граф, пересборка страниц.

Сделать:
1. **Мазок ничего не строит.** В клиенте `autoBuild` по умолчанию выключить для слоёв
   (регионы, генерации — по кнопке тоже). Раскладка помечается «не собрано».
2. **Предпросмотр грубой береговой линии на земле и на воде.** Текстура слоя материков
   (тексель 2 км, `LayerMap`, уже есть в раскладке) в шейдерах террейна и воды
   (`editor_overlay.hlsli`, сейчас только сетка регионов, выделение и кисть — 12 `float4`
   в `scene.editor`): рисовать изолинию «суша/море», которой станет слой, — для регионов
   «руками» порог 512 (см. `RegionSettings::manual`), для сгенерированных — `painted over made`
   по `layerBase` (`world_layout.hpp`). Это пункт «Слой на самой земле» из D147. Загрузка
   текстуры — только изменившиеся плитки слоя (`LayerMap` хранит плитки 32 × 32).
3. **Сборка по кнопке** (Build / Enter, и предложить при выходе из вкладки World shape):
   только те прогоны, чьи входы изменились — **кэш прогонов** в `generateLayoutWorld`
   по хешу входов (`generationLayout(...)` + латитуда + начало координат); неизменённые
   генерации берутся из кэша (в памяти — ограниченно, на диске — как страницы). На выходе
   сборки: генеративная береговая линия, рельеф, реки (п. 3 — только изменённые массивы),
   страницы (п. 3.6 — только затронутые).
4. Бесшовная подмена остаётся как есть (D151: старый мир на экране, `HoldPass`).
- Критерий: мазок — ноль работы генератора, предпросмотр виден в том же кадре; Build после
  правки одного региона референса — секунды, не минуты.

## 5. Порядок

1. Починить 4 GPU-теста (чтобы было по чему ловить регрессии).
2. П. 1 без фундамента: `cells`, климат, маска, копии поля, временные массивы, отпечатки
   по кускам.
3. П. 4.1–4.2 (мазок без сборки + предпросмотр) — независим, даёт сразу плавное рисование.
4. П. 3 (граф по массивам) — зависит от отпечатков по кускам из п. 1.
5. П. 4.3 (кэш прогонов) — зависит от п. 3 для рек.
6. П. 2 (фундамент кусками на 64 м) — самый крупный; после него убрать `foundationStepFor`
   из генерации больших миров.

## Чего не ломать

- Отпечатки обычных миров (4242 → `b2f7ddb91db7a2b2`, 7 → `12b71a77ce8201b`) и
  `--grow` (0 изменённых клеток/точек старого региона) — пока шаг не меняет генерацию
  намеренно; если меняет — записать в DECISIONS, почему.
- Детерминизм: одинаковые входы — одинаковые байты, порядок обхода кусков фиксированный.
- Правки истории мира (`world_delta`, `EditLayer`) лежат в мировых метрах — координаты мира
  не сдвигать.
