# VG1 — фундамент GPU-submission и трава одним draw

Дата: 2026-09-16. Первый шаг дорожки виртуальной геометрии
([архитектура](../../virtual_geometry_architecture.md), разделы 20–22;
размещение в плане — раздел 0b).

## Что было нельзя

Движок **вообще не умел** compute-пайплайны, storage-буферы и indirect draw,
хотя SDL3 и shadercross умеют всё три. Без этого ни одна часть архитектуры,
кроме уже реализованной террасы, не могла быть начата.

Трава при этом делала **до 341 draw call в кадре** (1283 суммарно по одиннадцати
сценариям) — по одному на блок земли и ярус.

## Что сделано

### Движок

`Device::makeCompute`, `makeBuffer`, `readBuffer`; `RenderPipeline::dispatch` и
`runDispatches`; `DrawItem::indirect/indirectOffset/indirectDraws`. Compute идёт
после загрузки инстансов кадра и до первого render pass — оба условия
вынужденные: compute pass нельзя открыть внутри render pass, а работа существует
ровно для того, чтобы прочитать только что загруженное и записать то, что
сейчас будет нарисовано.

### Ядро отбора кластеров

`engine::ClusterCuller` + `cluster_{geometry.hlsli,reset,cull}.hlsl`.

Правило — **разрез, а не порог**: кластер рисуется, когда его собственная
спроецированная ошибка укладывается в допуск, **а родительская — нет**. Тогда
вдоль каждого пути иерархии выбирается ровно один уровень, без дыр и без двойного
покрытия; именно это делает разрез DAG бесшовным. Плоский список инстансов — то
же правило с бесконечной ошибкой родителя, поэтому расстановка и иерархия не
могут разойтись в понимании «достаточной детализации».

Четыре GPU-теста сверяют ответ карты со **вторым** воплощением того же правила на
CPU: culling, который молча оставляет всё, и culling, который молча не оставляет
ничего, оба рисуют картинку.

### Трава: 341 draw → 1

Один draw на всё поле. Держал её раздробленной **собственный uniform draw'а**:
каждый блок земли толкал свой morph, свой уровень страниц, уровень родителя и шаг
кандидатов, а uniform принадлежит вызову отрисовки. Остальные двенадцать чисел из
шестнадцати оказались одинаковыми для всех блоков кадра.

Эти четыре числа теперь упакованы в **один дополнительный float** на кандидата:
пять бит уровня и уровня родителя, четыре — log2 шага, восемь — morph. Шаг morph
в 1/255 — это lerp, который никто не увидит, а весь код остаётся внутри точного
целочисленного диапазона float.

| | было | стало |
|---|---:|---:|
| draw calls травы, `forest-close` | 54 | **1** |
| draw calls травы, `steppe` (широкий план) | 341 | **1** |
| draw calls травы, сумма по 11 сценариям | 1283 | **11** |
| байт на инстанс | 28 | 32 |
| расхождение картинки | — | **0,0028%** пикселей в худшем кадре |

## Два бага, найденные тестами

Оба давали неправильную картинку без единой ошибки где-либо.

**Очередь диспатчей очищалась только внутри `run()`**, поэтому кадр, записавший
диспатчи иначе, переигрывал все предыдущие поверх своих.

**Индекс привязки следует тому, что точка входа реально использует**, а не тому,
что объявлено в файле. Шейдер сброса трогает только аргументы отрисовки —
reflection дал им слот 0, а вызывающий передавал туда список видимых. Сброс
обнулял не тот буфер, и счётчики каждого кадра были суммой всех предыдущих.
Теперь у каждого шейдера свои привязки и одна точка входа на файл.

## Тупик, который стоит записать

Сначала четыре числа блока лежали в `StructuredBuffer` вершинного этапа. Это
читалось **нулями**: у блоков получался уровень 0, страниц такого уровня нет, и
трава исчезала целиком. Причина — storage-буферы вершинного этапа адресуются
**после текстур, которые этот этап реально использует**, а не по номерам
регистров, объявленным во включаемых файлах. Здесь объявлено двенадцать текстур,
используется восемь, свободного регистра ровно на восьмой позиции нет, и
согласовать номер с отражением нечем.

Хуже отладки было то, что пока трава невидима, **любая проба показывает «ничего
не изменилось»**: и снятие альфы, и подмена индекса, и `SV_InstanceID`. Несколько
часов ушло на выводы, которые все были следствием одного симптома. Отсюда правило:
проверять новую возможность движка отдельным GPU-тестом **до** первого
применения, как это сделано для compute, — и цветовая проба на траве бесполезна,
потому что тинт умножается на текстуру карточки; годится только снятие альфы,
и только когда трава заведомо рисуется.

Поэтому поддержка storage-буферов вершинного этапа в `DrawItem` **откачена**:
непроверенный API в движке и есть причина этого тупика. Вернуть её следует
вместе с GPU-тестом на offscreen-цель.

## Чего здесь нет

- Деревья по-прежнему 12 draw (пять моделей × уровни) плюс общий батч карточек.
  Свести их в один — это indirect multi-draw поверх уже готового `ClusterCuller`;
  сделано не было.
- GPU-компактизации кандидатов: 114 688 кандидатов по-прежнему загружаются и
  отбрасываются в вершинном шейдере. Один draw убрал команды, не работу.
- `ClusterCuller` пока не используется ни одним проходом игры: он проверен
  тестами, но не подключён. Это следующий шаг.
- **FPS не измерялся и не заявляется.** Прогоны `--measure` до и после шли по
  разным траекториям камеры (`1st / free flight` против `target LOD 3`) и
  несравнимы; сравнивать честно можно только число draw calls и картинку.
